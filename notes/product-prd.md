# 简幕产品需求说明（PRD）

2026年11月19日更新。

本文写简幕做什么、为谁做、分几版发、每一步做到哪里算完，以及几条不能破的规矩。代码怎么组织、按什么顺序搭，见[架构设计](architecture.md)。

## 1. 结论

**给谁用**：首先是开发者本人，B 站和 YouTube 都常看，长视频多，一个窗口常开几十个标签页；其次是有同样习惯、愿意用自己 API 密钥的中文用户。

**解决什么**：几分钟内判断一个长视频值不值得看、重点看哪段；决定看了，再陪着精读。

**路线**：

| 步 | 做什么 | 做完的标准 |
| --- | --- | --- |
| 1 | 在新版里做「打开就出结论」（F10） | 打开开关后，B 站上超过设定时长的视频一打开就生成，结论显示在播放页卡片上，不用点 |
| 2 | 换到新版：开发者本人停用旧版，用新版日用 B 站（[架构设计](architecture.md)第 12 节第 9 步） | 只有两条：概览和问答在真实 B 站页面上不比旧版差；「打开就出结论」能用。B 站付费判断照常核对一次，不算门槛；旧版资料不迁移（开发者本人 2026-11-17 定），旧格式备份的读取靠自造样例的测试保证 |
| 3 | 首发：在 GitHub 发只支持 B 站的版本，不等 YouTube | 下面的首发范围都做完；开发者本人用新版日用 B 站；陌生人照 README 几分钟能装上，并在 B 站走通主流程 |
| 4 | YouTube 版：两站一个侧边栏 | 真实页面验证通过才发；开发者本人看两站都用简幕；陌生人在两站走通主流程 |
| 5 | 更新一、二、三 | 小步快发，某一项没准备好就顺延到下一次，不拖住整次更新 |

主流程指：打开一个视频，读到平台字幕，看到结论和章节，做引用问答。单靠导入字幕不算。

**首发范围（B 站版）**：

- B 站上现有的功能（F01–F08、F12–F15、F19–F21），含已经做完的本窗口全部生成和稍后再看粗筛。
- 新加：速览和精读两种模式，以及自动切换（第 6 节）；打开就出结论（F10）；解释当前画面（F11）；推理强度可调（F09）；悬停才出现的笔记图标（F08）。
- 发布必需项：首次启用确认（F22）、隐私政策、README（演示、安装和更新步骤、中英文）、Releases 里的 zip 和校验值、商标检索。

**成功标准**：首发看第 3 步那两条，「两站都用」在 YouTube 版。想要尽量多的 GitHub 星，不定数字；扩展里不加统计，日用与否由开发者本人判断。

发版和对外宣传，每次都要开发者本人同意。

## 2. 现状和要解决的问题

**现状**：旧的私有版开发者本人几乎每天都用，最常用概览和章节、问答。最烦两件事：YouTube 上用不了；每次都要手动点开、点生成，再干等结果。新版在这个仓库里重写，开发者本人 2026-11-17 起用它日用 B 站；首发要带的新功能（第 1 节）都已经做进主线，还没发版，发布必需项还没做完。

**要解决的问题**（依据只有开发者本人的使用习惯，没有其他用户数据）：

1. 长视频要先看结论和章节，再翻字幕，然后决定看不看；结论要来得快，打开就该看到。
2. 短视频不需要概览，主动弹出只会打扰。
3. 标签页太多，稍后再看也要再筛一遍，挨个点开太慢。
4. 两个站分在两套工具里。B 站约占看视频时间的三分之二，YouTube 约占三分之一。
5. 外语视频一半为了拿一手信息，要中文结论和中英对照；一半为了学英语。
6. 记笔记太麻烦，希望 AI 来写，或给出候选一键收藏。
7. 自己愿意多用强模型和自动功能，新用户的默认值仍要省钱。
8. 回答要能回到视频的时间点和字幕原文，自己核对。

**卖点**只讲三条：两个站一个工具（YouTube 版起）；打开就出结论，一个窗口的视频一次判断完；用自己的模型，每个功能单独调推理强度。B 站官方总结照常显示，简幕再补上结论和章节。代价照实说：自备密钥、费用自担，手动安装和更新。

## 3. 形态

- Chrome 扩展（Manifest V3）。在 GitHub Releases 发 zip，用户解压后在开发者模式下加载。暂不上架 Chrome 应用商店，以后再评估；Edge 不是前提。
- 更新靠用户解压新版覆盖同一个文件夹再重新加载。构建带固定的 `key`，扩展身份从第一个公开版本起不变；覆盖更新后身份和本机资料要能保留，没验证通过不发布。
- 没有开发者后端，不要账号，不放广告和统计，不加载远程代码，不做变现。用户自带 API 密钥，资料存在本机。新安装默认省钱：自动功能和推理强度都关。
- 底线：资料始终归属正确的视频、分 P 和字幕版本；部分失败保留已完成的；网页不能冒充用户触发花钱的操作；不拖慢播放页，和沉浸式翻译同时装也正常；报错写成「原因、影响、下一步」。
- 来历：从 Digest for Bilibili 0.4.6 分叉（MIT 许可），不再同步。名字、结构、界面、图标和提示词都换成自己的；有测试的纯逻辑是移植的，所以仍含它的代码。

「首发」指 B 站版。YouTube 部分一律在 YouTube 版。

| F06 | 引用问答 | 速览和精读共用问答抽屉；回答带时间点和字幕原文，点了跳回；找不到依据如实说；每问单独回答 | 首发 |
| F07 | 划词解释 | 精读里选中字幕点「解释」，结合前后文说明 | 首发 |
| F08 | 时间戳笔记与悬停图标 | 悬停才出现的笔记图标和 `n` 键，记下时间点和这一刻的字幕；可润色、编辑、导出 Markdown 和学习稿 | 首发 |
| F09 | 推理强度 | 每个用到模型的功能单独选关、低、中、高，新安装全关；不支持的档退到最接近的一档并说明 | 首发 |

## 5. 不做和以后再看

以后再看，不是承诺：问答边写边显示；上架 Chrome 应用商店；上架 Edge 加载项商店；笔记导出到 Anki；音频转写（取音频等于做下载工具，隐私、权限和费用都要另算）。

不做：YouTube 稍后再看；跟读和听写；直接同步 Obsidian 或 Notion（笔记本只导出 Markdown）；无密钥用法；自定义提示词；本地 OCR；平台自带的机器翻译字幕轨；小红书、抖音和任意网页摘要；云同步、自营账号、服务器 Cookie 池；评论采集、账号运营、改收藏；思维导图、PPT 和播客音频；跨视频的知识库问答；扩展里检查新版本。

## 6. 速览和精读

学英语模式在更新三，其余首发就有。

### 6.1 定义

模式按「此刻想从视频得到什么」分，不按视频语言分。

| 模式 | 什么时候 | 侧边栏显示什么 |
| --- | --- | --- |
| 速览 | 还没决定看不看 | 结论和章节，标出重点；每章能展开看要点和字幕；可以提问 |
| 精读 | 决定要看 | 跟着播放高亮当前章节和句子；提问、划词解释、解释画面、记笔记 |
| 学英语（更新三） | 拿视频练英语 | 双语字幕、逐句播放、挑出的词和表达 |

为拿信息看的英文视频也用速览和精读：结论和章节用中文，字幕中英对照。

### 6.2 打开视频时进哪个模式

按顺序取第一条成立的：

1. 这次观看里用户手动选过的模式。
2. 用户给这个频道选过的模式。频道在 B 站指 UP 主。
3. 按时长：不到 5 分钟进精读，不主动给概览；5 分钟及以上进速览。时长不知道时按长视频算。

### 6.3 自动切换

- 只有一种：长视频在速览里连续播放满 1 分钟，切到精读。顶部显示一行「已切到精读」，点一下回到速览。
- 播放时长按实际播放累计：暂停不清零，拖动跳过的和广告不算，倍速按真实时间算，后台标签页在播也算。
- 每次观看最多自动切一次，撤销后这次不再切。换视频算新的一次；同一标签页刷新同一个视频仍算同一次，状态和累计时长接着用。
- 这次观看里手动选过模式，就不自动切。频道偏好只管打开时进哪个模式，不挡自动切换。
- 问答抽屉开着时照样计时和切换，抽屉、草稿、焦点和在途回答都保留。
- 「已切到精读」这一行只在看得见、点得到时计时。侧边栏关着时照样计时和切换，卡片跟着收起，用户手动展开或收起过的除外。

### 6.4 手动切换和按频道记住

- 侧边栏顶部随时能切换模式。主动点一次切换就记住这个频道，以后默认进这个模式。撤销自动切换、开问答抽屉、输入、发送、点引用都不算手动切换。
- 频道偏好长期存在本机，设置页可以清除；正在看的视频的模式只在本次浏览器会话里保留。

### 6.5 播放页卡片跟着模式走

卡片只在 B 站有（F14）。

- 速览时展开，显示结论和章节；精读和学英语时收起成一行；短视频默认收起。
- 用户在这个视频里手动展开或收起过，以用户的为准，直到换下一个视频。
- 收起时不读数据；后台打开的标签页第一次切到前台才读。「打开就出结论」在后台生成好的，切过去时直接显示结论。
- 提问入口只在侧边栏，卡片不加。

### 6.6 速览里显示什么

- 有结果就直接显示：B 站官方总结和 UP 主分段，之前生成过的概览。没有结果时显示「生成概览」按钮和字幕，有字幕就能提问。
- 开着「打开就出结论」：超过设定时长的 B 站视频一打开就生成，后台打开的标签页也排队生成、正在看的先生成，卡片和侧边栏逐块显示已完成的章节，结论写完就显示在卡片上。没到设定时长的不自动生成。设定时长调到 5 分钟以下时，短视频也会生成，但界面仍进精读。
- YouTube 版：YouTube 不自动生成，先提示读取字幕，读到后显示实际轨道和「生成概览」按钮。

## 7. 隐私、同意和费用

### 7.1 隐私原则

- 浏览器的站点授权、首次启用确认、发给模型的数据同意是三件事，分开记、互不代替。启用了不同意发给模型，字幕和官方总结照样能读，只在本机处理。
- 发给模型的只有当前功能需要、数据说明里列出的内容：字幕；标题、作者名、简介、时长和 B 站官方总结；用户选中的文字和问题；解释画面时的当前一帧和前后字幕。登录 Cookie、登录凭证和平台返回的字幕地址不发。密钥不进网页、日志和备份。
- 权限从严：必需的只有 `sidePanel`、`storage`、`scripting` 和 B 站的主机；YouTube 和 AI 服务地址都按来源逐个可选申请。不申请 `tabs`、`activeTab`、`cookies`、`downloads`、`debugger`、`tabCapture`、`desktopCapture`、访问所有网站和麦克风。带密钥的请求不跟随重定向。扩展只看得到已授权网站标签页的地址和标题。

### 7.2 数据同意

这里的同意只管「把内容发给模型服务」。

- 发给模型的内容类别、用途、接收方、触发方式或范围有实质变化，同步改数据说明；超出原来同意的范围，先请用户重新同意再启用。从「点了才发」变成自动发或批量发也算超出，只改文字不算。
- 要重新同意就升版，旧同意随之失效。首发之前不再升版（开发者本人 2026-11-18 定，这期间只有他一个人在用）：现在是第 5 版，之后新增或改动的条目并进这一版，说明变了他会被重新问一次；首发时版本号从 1 重新算，对所有人都是第一次同意。首发以后每次扩大范围都升版。
- 首发的数据说明要写清：打开「打开就出结论」后，B 站上超过设定时长的视频一打开（后台打开的标签页也算）就自动发送字幕、标题和时长、作者名和简介；没开时只在用户点按钮时发。解释当前画面发送当前一帧和前后几句字幕。YouTube 版加上 YouTube，只在用户点按钮时发。
- 以后的更新里，自动排队、自动截多帧、自动准备精华候选、自动挑词、把英语水平发给模型，都超出原来的范围，上线前升版、重新同意。
- 首发对所有人都是第一次同意。以后说明更新时，界面说清这次多了什么，不误报成密钥问题。
- 设置页的数据说明、首次启用说明、代码里的同意表、`PRIVACY.md`、README 保持一致，改一处同步其余几处。

### 7.3 首次启用确认

- 安装后先不读任何视频数据。第一次打开侧边栏或设置页时，在扩展自己的页面里说明，用户点「启用简幕」才开始读。确认前什么都不读、不计时，卡片和播放器图标也不出现。
- 说明里写三样：读什么（视频信息、字幕、B 站登录状态（只看是否已登录，不读 Cookie 内容）、官方总结和 UP 主分段、观看状态；本窗口全部生成时已授权网站标签页的地址和标题；打开「打开就出结论」后已授权网站各标签页的地址，包括后台打开的；粗筛时的稍后再看列表和每个视频看到哪里；点「解释当前画面」时的当前一帧）；用来做什么（显示、定模式、作为生成和问答的材料）；本机存什么、存多久、怎么清。
- 只确认一次。读取的内容或用途有实质变化，照 7.2 节重新确认，说明只列新增的内容；首发之前同样不再升版，首发时版本从 1 起。「清除全部数据」会清掉确认。

### 7.4 隐私政策

- 放在公开仓库的 `PRIVACY.md`，不另建网站，按首发的实际行为新写，不从旧版复制。
- 写清数据来源、本机读取什么（和首次启用说明一致）、什么时候发什么给模型、接收方（预设的服务商附政策链接）、存储和删除、权限、记住密钥未加密、联系方式（issue 地址和能收信的邮箱）。中英文同步。
- 「扩展不读 Cookie 内容」和「浏览器随请求带上登录状态」分开写。不写本机资料已加密。换 AI 地址后回收旧授权，旧版从没成功过，新版修好并实机验证后才写进政策，并写明可能保留的情况。

### 7.5 费用

- 不承诺免费或统一费用。花额度的操作开始前说清：批量处理先说数量，开关旁写明后果，推理强度旁写明越高越贵，「整理字幕」按钮旁写明要用额度、一个长视频大约和翻译一遍差不多。
- 问答每问最多送约 6 万字的字幕（短的整份送），长视频每问比只送几段时更花额度；同一个视频接着问时，服务商的前缀缓存能省下一部分，但不保证。
- 模型请求同时最多 6 个：长视频的概览、翻译和批量生成更快，花的额度不变；个别服务商会因此限流，限流和过载时等一会儿自动再发一次。
- 关页面、取消、失败都不保证服务商不计费。取消和后台中断后不自动重发；偶发失败在次数上限内自动重发，重发也可能计费。

## 8. 平台读取的规矩

两个平台都没给过许可。开发者本人接受平台可能不同意的风险，按下面的条件做；平台或权利方正式要求停止时就停。

### 8.1 B 站

- 只给已登录用户读：每次读取先确认登录，未登录不读任何平台内容，提示登录或导入字幕。
- 只读能确认是非付费普通视频的内容。付费和充电专属内容不读，付费状态确认不了时也不读。
- 不下载音频或视频；不读 Cookie 值，不冒充其他客户端或设备。
- 保持低频：按站点限速；批量处理要用户先确认数量，条目之间有间隔。
- 被平台拒绝、限流或遇到人机验证就停下，按站点退避，不换方式反复试。例外只有两个：第一次被拒时重新准备一次再试；没有字幕轨，或者字幕列表、字幕文件读取失败时，用官方总结那次回复里附带的 AI 字幕，不另外向平台要字幕，注明来源；这次读取里平台拒绝过就不用。这份字幕在播放页上不一定看得到，照用（开发者本人 2026-11-18 定）。用过它的视频，离上次向平台读字幕过了 10 分钟（和官方总结重问同一个间隔）再打开时，再试一次平台字幕，读到了就换回平台字幕；站点退避期内不试（开发者本人 2026-11-19 定）。
- 平台返回的字幕地址不落盘。
- 请求签名和读取实现公开，进公开仓库和 Releases 的 zip。不抄第三方接口文档，不带它们的文字和注释，沿用 MIT 代码的部分保留版权声明。

### 8.2 YouTube

1. 只读用户正在看的视频、平台已经在页面上给这位观众的字幕。不读 Cookie 内容，不自己构造平台用来校验访问权限的数据，不冒充其他客户端或设备，不复用、重放或伪造页面的校验信息，不引起机器翻译字幕轨的请求，不改变播放器状态（用户点时间点引起的跳转除外），不绕过登录、付费、年龄或地区限制。
2. 至少读得到播放器当前给这位观众显示的那一条字幕轨的完整正文，时间轴对得上；其余的人工轨和原语言自动轨读得到就给，读不到不拦发布（开发者本人 2026-11-18 定，原来要求每条轨都读得到）。只读到当前可见的一部分不算。
3. 读到的字幕必须属于当前视频。开始读、正文返回、写缓存前都要核对，归属不了的一律丢弃。这条不满足不能发布。
4. 没有字幕、空文件、被限流、需要登录，各有能辨认的信号才报，其余报「暂时无法读取」。
5. 只在用户点读取时读当前视频，自动生成和批量处理不读。遇到限流或人机验证立即停下，不自动换路线。用户不用复制 Cookie、不用开发者控制台。

### 8.3 真实页面检查

两站的真实页面检查由开发者本人做，或者在他点名时由协助他的人在他的浏览器里做（开发者本人 2026-11-18 定）：一个个打开、看页面，不用脚本遍历。没取得平台的明确许可、或独立评估确认有法律依据之前，不做无人值守的自动检查。样本和记录不进公开仓库。
