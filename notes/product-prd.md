# 简幕产品需求说明（PRD）

2026年11月7日更新。

本文说明简幕的目标形态：它是什么、为谁做、有哪些功能、每项做到哪里算完成、分几个版本上线。怎么分阶段做、依赖什么、怎么验证、什么条件下发布，见[简幕重构与双站首发方案](dual-site-launch-plan.md)（下称「方案」）。代码怎么组织，见[架构设计](architecture.md)。同一件事只在一处详写，本文碰到实现问题只给链接。

## 1. 产品定位

**一句话**：简幕是一个 Chrome 扩展，帮你在几分钟内判断一个 B 站或 YouTube 长视频值不值得看、重点看哪段；决定看了，再陪你精读。

**为谁**：

- 首先是开发者本人：B 站和 YouTube 都常看，长视频多，一个窗口常开几十个标签页。
- 其次是有同样习惯的中文用户：看长视频前想先知道值不值得看，愿意用自己的模型 API 密钥。

**目的排序**：

1. 自用。开发者本人每天用得上，是所有取舍的第一标准。
2. 开发者本人的公开作品。代码、文档和设计取舍经得起别人看。
3. 公开用户。在 GitHub 公开发布，别人照 README 就能装来用。

公开发布的目标是尽量多的 GitHub 星（第 2 节）。不做变现。

**主线**：帮用户几分钟内判断一个长视频值不值得看、重点看哪段。这条主线按开发者本人的使用习惯（第 3 节）定，是自用驱动的选择；其他用户是不是同样需要，没有验证过。精读、笔记本、学英语都围绕「看这个视频」展开，不另起产品线。

**形态**：

- Chrome 扩展（Manifest V3）。首发指在 GitHub 公开发布可安装的版本：Releases 里的 zip，用户解压后在开发者模式下加载。暂不上架 Chrome 应用商店（第 5.3 节），Edge 不是首发前提。安装和更新的约束见方案第 7.5 节。
- 没有开发者后端，不要账号。用户自带模型 API 密钥，资料存在本机。
- 不做无密钥用法，例如把提示词复制到网页版 AI 里用。
- 功能范围以本文为准，不为凑卖点另加功能。

**来历**：简幕最早从 Digest for Bilibili 0.4.6 分叉（MIT 许可），不再与它同步。首发前把内部名字、代码结构、界面、图标和提示词换成简幕自己的；有测试的纯逻辑从原有代码移植，所以首发时仍含有 Digest for Bilibili 的代码，版权说明见第 10 节。

## 2. 成功标准

- 连续两周，开发者本人看 B 站和 YouTube 时都用简幕，不再打开别的视频总结工具。
- 代码仓库公开，有一个面向访客的作品展示页（README）。
- 陌生人照 README 几分钟内装上，并在两站走通主流程。
- 尽量多的 GitHub 星。不定具体数字，不作承诺。

扩展里不加使用统计，第一条由开发者本人按实际使用判断。

## 3. 要解决的问题

依据是开发者本人的使用习惯。简幕没有使用数据，不按假想用户做功能。

1. **长视频要先判断值不值得看。** 习惯是先看一句话结论和章节，再浏览各段内容和字幕，然后决定看不看。平台自带的总结只在部分视频上有，两个站各管各的。
2. **短视频不需要概览。** 一两分钟的视频很少看概览，主动弹出总结只会打扰。
3. **标签页太多。** 一个窗口常开几十个视频标签页，挨个点开判断太慢。
4. **稍后再看要再筛一遍。** 稍后再看里只存当天看不完、又有价值的长视频，平时不囤，回头看时仍要排个先后。
5. **两个站分在两套工具里。** 看视频的时间 B 站约占三分之二，YouTube 约占三分之一，希望用同一个侧边栏。
6. **外语视频有两种看法。** 一半是为了获取一手英文信息，要中文结论和中英对照字幕；一半是为了学英语，要逐句听、挑词和表达。
7. **记笔记太麻烦。** 以前不记笔记就是因为麻烦。开发者本人在 Digest for Bilibili 里攒下的资料只有 4 条概览，没有一条笔记。希望笔记由 AI 来写，或者给出候选、一键收藏。
8. **愿意多用模型。** API 额度充足，希望能开强模型、多用自动功能；新用户的默认值仍要省钱、可控。
9. **回答要能核对。** 问视频内容时，答案要能回到视频的时间点和字幕原文，自己核对。

## 4. 卖点

对外只讲三条：

1. **两个站一个工具。** B 站和 YouTube 用同一个侧边栏看结论、章节、字幕并提问。官方工具各管各的，YouTube Ask 目前只在部分视频、部分国家可用。
2. **几十个标签页一次判断完。** 当前窗口里开着的 B 站视频一页列出一句话结论，按判断分组，可跳过的一键关掉（标签页粗筛，更新一）。YouTube 标签页受读取边界约束（F16）。
3. **用自己的模型。** 想用多强用多强，每个功能可以单独调推理强度；资料存在本机，要发给模型的内容只发给用户自己选的服务。

对外文案怎么写见第 11 节。

和平台自带工具的区别：

| | B 站官方 AI 总结 | YouTube Ask | 简幕 |
| --- | --- | --- | --- |
| 站点 | 只在 B 站 | 只在 YouTube | 两站同一个侧边栏 |
| 覆盖 | 部分视频有 | 目前部分视频、部分国家可用 | 两站普通播放页上有字幕的视频（B 站要登录，YouTube 要用户先读取文字稿） |
| 模型 | 平台自己的 | 平台自己的 | 用户自己选，按功能调推理强度 |
| 批量判断 | 没有 | 没有 | B 站：本窗口全部生成、稍后再看粗筛；标签页粗筛（更新一）。YouTube 首发单视频手动生成 |
| 费用 | 免费 | 免费 | 付给用户自己的模型服务 |

简幕不取代 B 站官方总结：侧边栏和播放页卡片直接显示官方总结和 UP 主分段，再用用户自己的模型补上一句话结论和章节。代价也要说清：要自备密钥，费用自担；要在开发者模式下手动安装，更新也要手动（方案第 7.5 节）；没有字幕的视频要导入字幕文件才有完整概览，B 站可以先看官方总结（F05）；YouTube 每个视频要先手动读取文字稿，首发不自动生成，也不批量生成（F02、F10、F13）。

### 5.3 候选

- 问答边写边显示（主动用流式输出）。首发只要求兼容强制返回流式的模型网关（F19）。
- 上架 Chrome 应用商店：暂不做，以后再评估。
- Edge 加载项商店上架。
- 笔记导出到 Anki。
- 音频转写。首发和三次更新都不做，理由：取 B 站音频等于做下载工具的事，要长期跟着平台的访问限制改代码；音频上传的隐私、权限和费用都要另外处理。

### 5.4 不做

- YouTube 稍后再看。
- 跟读和听写：要麦克风权限和评分。
- 直接同步 Obsidian 或 Notion：笔记本只导出 Markdown。
- 无密钥用法。
- 本地 OCR：读画面上的字交给能看图的模型（F11）。
- 自定义提示词：提示词内置，按模式写好。
- 平台自带的机器翻译字幕轨：中英对照用用户自己的模型翻（F04）。
- 小红书、抖音、任意网页摘要。
- 云同步、自营账号、服务器 Cookie 池。
- 评论采集、账号运营、修改收藏。
- 生成思维导图、PPT 或播客音频。
- 跨视频知识库问答。
- 扩展里检查新版本：不新增对外请求。

## 6. 三种模式

**状态**：速览、精读和自动切换首发待实现；学英语在更新三。

### 6.1 定义

模式按「此刻想从视频得到什么」划分，不按视频语言分。

| 模式 | 什么时候 | 侧边栏显示什么 |
| --- | --- | --- |
| 速览 | 还没决定看不看 | 一句话结论、章节，重点章节标出来；每个章节能展开，看这一章的要点和这一段字幕；可以提问，不用切模式 |
| 精读 | 决定要看 | 跟着播放走：当前章节和当前句高亮；随时提问、划词解释、解释当前画面（仅 F11 进包时）、存笔记 |
| 学英语（更新三） | 拿这个视频练英语 | 双语字幕、逐句播放、AI 挑出的词和表达（F18） |

为获取一手信息看的英文视频，也用速览和精读：结论和章节用中文，字幕中英对照（F04）。

### 6.2 打开视频时进哪个模式

按顺序取第一条成立的：

1. 这次观看里用户手动选过的模式。
2. 用户给这个频道选过的模式。「频道」在 B 站指 UP 主，在 YouTube 指频道。
3. 按时长：不到 5 分钟的短视频进精读，不主动给概览；5 分钟及以上的长视频进速览。

自动生成打开时，B 站短视频也会生成概览（F10），但界面仍进精读，概览放在精读的章节里，不推到最前。

### 6.3 自动切换

- 只有一种：长视频在速览里连续播放满 1 分钟，切到精读。顶部显示一行「已切到精读」，点一下回到速览。
- 「播放满 1 分钟」按实际播放时长累计：暂停不清零；拖动跳过的部分不算；广告不算；倍速按真实经过的时间算；标签页在后台但视频在播时照样计时。
- 每次观看最多自动切一次。点「已切到精读」回到速览后，这次观看不再自动切。换一个视频算新的一次观看；同一标签页刷新同一个视频，仍算同一次观看，这次的模式（含手动选过的）和「已自动切过」都保留，累计的播放时长也接着算。
- 这次观看里手动选过模式时，不自动切。频道偏好只决定打开时进哪个模式（第 6.2 节），不挡自动切换。
- 问答抽屉开着时照样计时和切换。抽屉、草稿、焦点和在途回答都保留，收起后显示当时实际的模式。
- 「已切到精读」这一行只在看得见、点得到时计时：被抽屉或优先级更高的提示挡住、标签页不在前台时暂停，免得用户还没看到就错过了不记频道的撤销。
- 侧边栏关着时照样计时和切换，播放页卡片跟着收起；用户在这个视频里手动展开或收起过的，以用户的操作为准（第 6.5 节）。

### 6.4 手动切换和按频道记住

- 侧边栏顶部随时可以切换模式。
- 手动切换一次，就记住这个频道：以后打开这个频道的视频，默认进用户选的模式。点「已切到精读」那一行回到速览，是撤销自动切换，不算手动切换，不记住频道。只有主动点模式切换才算手动切换：开问答抽屉、输入、发送、点引用都不算。
- 设置页可以清除记住的频道。
- 频道偏好长期存在本机。正在看的视频的模式只在本次浏览器会话里保留，浏览器重启后按第 6.2 节重新判断。

### 6.5 播放页卡片跟着模式走

卡片只在 B 站有（F14）。

- 速览时展开，显示结论和章节。
- 精读和学英语时收起成一行。
- 短视频默认收起。
- 用户在这个视频里手动展开或收起过，就以用户的操作为准，直到换下一个视频。
- 收起时不读取数据。后台打开的标签页，第一次切到前台时才读（F14）。
- 速览的提问入口只在侧边栏，卡片不加（F06）。

### 6.6 自动生成关着时，速览显示什么

- 已有的结果：B 站官方总结和 UP 主分段，之前生成过的概览。
- 什么都没有时：B 站显示「生成概览」按钮和字幕。YouTube 没有平台官方总结，还没读取文字稿时先显示读取提示（F02），读到以后显示实际轨道、字幕和「生成概览」按钮。有可用字幕就能提问（F06）。
- 开了自动生成：打开 B 站视频就开始生成，长视频在速览里逐块显示已完成的章节；短视频也生成，但界面仍进精读，结果放在精读的章节里（第 6.2 节、F10）。YouTube 不自动生成，显示和关着时一样。
- YouTube 进精读时（短视频打开就进，长视频播放满 1 分钟切过来），还没读取文字稿就显示同一条读取提示（F02），不触发读取。

### F01 视频识别与侧边栏

**状态**：B 站当前已实现，含没连上时提示刷新；YouTube、按模式重排侧边栏、自动补上连接、分 P 超范围的提示首发待实现。

行为：

- 点浏览器工具栏上的简幕图标打开侧边栏。侧边栏显示视频标题、作者（UP 主或频道名）、字幕的语言和来源，下面按当前模式排布（第 6 节）。
- 还没完成首次启用确认时，侧边栏只显示启用说明和「启用简幕」按钮，不读当前视频（F22）。
- 认得出的页面：B 站播放页和列表播放页（含分 P）；YouTube 桌面版普通观看页（`/watch?v=…`）。
- 侧边栏跟着当前标签页走。切换标签页、站内换视频、前进后退时，界面立刻换成新视频；旧视频的请求回来只写回旧视频的记录，不覆盖新视频的界面。
- 同一视频的播放列表参数、起播时间、分享追踪参数不产生新记录。B 站同一视频的不同分 P 算不同的视频，不混用字幕、笔记和问答。同一内容在两个站各传一份，算两个视频。
- 地址里的分 P 超出这个视频的分 P 数时，提示这个分 P 不存在，不悄悄换成第 1 P。
- 页面还没连上扩展时（例如扩展刚安装或刚更新），能自动补上就自动补上，补不上就提示刷新页面。
- 认不出当前页面时，统一提示「这不是简幕支持的视频页，或者简幕看不到这个页面」，并给出下一步。YouTube 还没启用时，提示里附一个「在 YouTube 上启用」按钮。启用之前简幕看不到 YouTube 标签页的地址，分不出这一页是不是 YouTube，所以不单独提示「这是还没启用的 YouTube 页面」。

边界：

- YouTube：Shorts、直播和直播回放、YouTube Music、移动版网页、付费或有年龄、地区限制的内容，首发不承诺。
- B 站：保留现有支持范围（含分 P）；番剧、付费、课堂等特殊内容不因本文自动增加支持。
- 不支持侧边栏接口（Side Panel API）的浏览器版本用不了，README 里写明。举例时只写实际核对过的浏览器和版本，不对某个浏览器品牌下整体结论。

完成标准：在真实 Chrome 里，B 站到 YouTube 再回 B 站来回切换、同一站里快速连续换视频、前进后退，侧边栏显示和保存的资料都属于当前视频。

### F02 字幕获取与阅读

**状态**：B 站当前已实现；未登录不读字幕的登录规则调整首发待实现（现有版本未登录时还能读到部分字幕，首发改为仅登录后读取）；按站点退避、字幕文件限流识别、平台返回的字幕地址不落盘首发待实现；YouTube 读取已有字幕首发待验证（第 10 步验证现有字幕读取；YouTube 找不到满足条件的路线，两站都不发布）；B 站选轨顺序和两站失败分类首发待实现。

行为：

- 读取视频可用的字幕轨，标明来源（人工字幕、自动字幕、用户导入；B 站还有官方总结附带的 AI 字幕）和语言。B 站可以切换轨道；YouTube 怎么换轨见下面的「YouTube 读取」。
- B 站默认选轨顺序：原语言人工字幕 → 中文人工字幕 → 原语言自动字幕，同时记下视频的音频语言。B 站的 AI 字幕按自动字幕算。B 站视频没有字幕轨或字幕文件读取失败时，可以用已经收到的官方总结附带的 AI 字幕兜底，不新发请求，注明来源；被平台拒绝或限流时一律停下，不用它。这份字幕确认对观众可见之前，首发默认不用（首发待验证）。
- YouTube 读取（候选设计，首发待验证，第 10 步）：
  - 读观看页文字稿面板里显示的文字和时间。默认读面板当前选中的原生轨，显示实际语言和可确认的来源，不按上面的顺序自动选轨，不遍历语言。面板当前选的是翻译项，或辨不清是不是翻译时不读，提示用户在 YouTube 面板里选原生轨；只是分不清人工或自动时，记成未确认。
  - 只有用户点读取按钮才读。打开侧边栏、进精读、提问、记笔记、解释当前画面都不触发读取。
  - 第 1 档，用户自己打开面板：侧边栏显示「请在视频简介中点『显示文字稿』（Show transcript），再回到简幕点『读取文字稿』。」用户点了才读。这也是第 2 档不通过时的退路。
  - 第 2 档，用户逐次委托简幕打开一次面板：第 10 步通过才显示这个按钮（通过条件见方案第 4.4 节，按钮随发行开关走），按钮写「打开 YouTube 文字稿并读取」。一次点击只授权当前焦点窗口、当前标签页、当前视频的一次打开。打开侧边栏、点「生成概览」、打开总开关、确认一批视频，都不顺带授权。换页、窗口失焦或撤权即作废，失败不重试。面板原已打开，或用户中途接手，就留给用户。面板保持可见，读完不关，留给用户。只在前台标签页上做，不替用户切标签页。
  - 换语言：用户自己在 YouTube 面板里换，简幕再读。候选设计里再加一种代换语言，同样第 10 步通过才显示，随发行开关走：面板已经打开，用户在简幕里明确选一个能识别为原生轨的目标，例如「切换到英文（人工字幕）」，简幕切一次。一次只切这个目标，不顺带开面板，不遍历，不选翻译项，不为恢复原状再切一次。目标、来源或翻译属性辨不清时，让用户去 YouTube 面板自己选。
  - 读取成功后显示实际轨道，例如「已读取英文人工字幕」，再提供「生成概览」。本机读取和付费发送是两个动作。
  - 简幕代操作时不碰字幕开关、音轨、音量和清晰度，不点面板里的字幕行。识别不了限流，或无法预先排除翻译或播放器副作用时，相应的代操作不启用。实机没遇到限流时，代操作默认不开（方案第 4.1 节第 4 条）。
  - 第 2 档和代换语言只是第 10 步的候选设计，分开验证，可以分别失败，失败层级见方案第 4.4 节。这是用户逐次委托简幕操作 YouTube 页面，不是平台许可（方案第 4.1、8 节）。
- 阅读：原文、译文、双语三种显示；当前句跟着播放高亮；点一句跳到对应时间；「回到当前句」；搜索原文和译文；复制和导出 SRT，内容与当前显示一致。正在播广告时高亮停在原处，点字幕、章节和引用都不跳转，提示广告结束后再试，不跳过广告。
- 读到的字幕缓存在本机，避免重复请求；用户可以主动刷新。时间轴和视频明显对不上的字幕给出提示，不当作可信字幕缓存。
- YouTube 自动字幕常有滚动重叠和重复的句子，要合并干净，不能因此出现重复句、错位的时间点或错误的引用。
- 站内换视频后，只用和当前视频对得上的字幕轨，不用换视频之前页面留下的旧数据，包括文字稿面板里留着的旧内容。无法确认属于当前视频的结果一律丢弃。
- 登录：B 站读字幕、官方总结和稍后再看都要先登录 B 站，未登录时提示「登录 B 站后可读取字幕，或导入字幕文件」。YouTube 只在平台明确要求登录时报「需要登录」，明确信号是什么，第 10 步实测后定；只看到空文件时报空文件，提示登录或导入，不判定为需要登录。登录只是读取的前提，不代表取得了平台的许可。
- 失败原因分开提示，至少分清：视频没有字幕、字幕是空文件、需要登录、被平台限流、视频不可用、网络错误、平台返回的内容格式变了。每条提示写成三段：原因、影响、下一步。YouTube 上各要有可辨的信号才报：面板没打开是待用户操作，提示用户打开；找不到入口可能是页面变了；加载中或空白不报空文件。认不出原因时报「暂时无法读取」，如实提示，不算分清了上面几种。

边界：

- 没有字幕的视频不转写音频，只能导入字幕文件。
- 取字幕被平台拒绝或限流时停下并提示，按站点退避（首发待实现），不自动换别的方式反复尝试，不绕开平台的访问限制。例外只有方案第 8 节第 1 项写的两个。字幕文件读取被限流也按限流处理，不再试下一条轨，也不重新列轨（首发待实现）。
- 平台返回的字幕地址不落盘，换语言时重新列轨（首发待实现）。
- YouTube 读取路线在第 10 步定，分两个节点，不混用：「选定候选路线」（按五条条件设计筛选，开发者本人审阅这条路线的条款说明）和「路线实机通过」（端到端通过加约 12 个真实视频实机通过）。五条条件见方案第 4.1 节，发布条件见方案第 9.3 节。
- 选定候选路线后，先用本机开发构建打通当前视频到原生字幕轨、正文和时间轴，在约 12 个样本里先看最快暴露问题的几个，再做路线专属的页面桥、模拟，以及本窗口全部生成里 YouTube 条目的清点和跳过，动态注册和端到端里的 YouTube 步骤同步完成。「本机开发构建」指字幕路线用的产品开发构建。路线打通时就要用页面已有数据的，只读页面桥的最小实现放进打通这一步。打通时在真实页面上看样本，就要按方案第 4.4 节实机清单的账号、身份、停止和记录规则做。读取实现首次推到公开分支或出现在公开 PR 之前，按实际行为补完方案第 8 节并审阅。
- YouTube 找不到满足条件的路线，两站都不发布。B 站请求签名和相关读取实现仍走自己的独立评估（第 10 节「合规」）。
- YouTube 的硬性限制不放松：不读 Cookie 内容，不自行计算或构造平台用于校验请求访问权限的数据，不冒充其他客户端或设备，不复用、重放或伪造页面为自身请求取得的校验信息，不引起机器翻译字幕轨的请求，遇到限流或人机验证立即停下。读取时也不改变用户的播放器状态，用户点时间点引起的跳转和开始播放另算；不绕过访问限制（方案第 4.1 节第 1 条）。
- 不要求用户复制 Cookie、手动取登录凭证或在开发者控制台里执行命令。

完成标准：

- 两站的样本视频（人工字幕、只有自动字幕、多语言轨、没有字幕、一小时以上、未登录）在真实 Chrome 里各有正确的结果和提示。

### F03 导入字幕

**状态**：B 站当前已实现；YouTube 首发待实现；换字幕后标注旧结果首发待实现。

行为：

- 导入 SRT 或 VTT 纯文本文件，上限 2 MiB、20,000 条。导入前写明要绑到哪个视频。
- 导入后优先用这份字幕并注明来源；可以移除，恢复用平台字幕。
- 导入的字幕存在本机单独的位置：「清除缓存」保留，「清除全部数据」删除。不进 JSON 备份，界面提醒用户自己留着原文件。
- 导入这一步不发给模型。之后用翻译、概览、问答、解释时，字幕文字才按已同意的范围发出。
- 换了字幕（导入、替换、移除）以后，依据旧字幕生成的译文和概览不删除、不改写，标成「基于旧字幕」；笔记和问答保留原文快照，不伪装成基于新字幕。

边界：导入是平台字幕缺失时的备用入口。只能靠导入、读不到平台字幕，不算 YouTube 支持完成。

完成标准：两站导入、替换、移除各跑通一遍；换字幕后旧结果的标注正确，笔记和问答没有丢。

完成标准：两站外文视频的翻译、停止、继续、换轨后对照不错位；自动生成开关的两种状态下，翻译时机与上面一致，YouTube 都是点了才翻。

### F05 概览与一句话结论

**状态**：当前已实现（B 站）；按速览重做输出、新判断档位、重点章节、只重写结论、停止和重新生成时的计费说明、没有字幕时的兜底、按实际依据标注、YouTube 首发待实现。

行为：

- 用字幕生成一句话结论和带时间点的章节，点章节跳到对应位置。结论和章节一律用中文，英文视频也一样。
- 一句话结论带观看判断，四档：推荐看、可以看、可跳过、信息不足。字幕覆盖不全或材料太少时判「信息不足」，并写明原因。粗筛的分组用同一套四档（F15、F16）。
- 速览里的章节要粗到几分钟内能扫完；每章能展开，看这一章的要点和这一段字幕。金句保留，作为笔记和精华候选的来源。
- 重点章节回答「重点看哪段」。写结论时，模型从这一版章节里选 0 到 3 章，不多发请求；判「可跳过」时也可以标出其中值得看的一段。章节行和时间轨上标出来。
- 什么时候标：结论依据这一版字幕章节，章节没有失败或截断的区间，结论完整，判断是推荐看、可以看或可跳过。「信息不足」、字幕覆盖不足、只有金句、官方总结、标题和简介、旧版未知都不标。B 站官方总结附带的 AI 字幕走了逐段生成的按字幕算，只读了官方提纲的不标。
- 重点跟着结论走，只对写这条结论时的那一版章节有效。模型选的章节要和现有章节的起始时间对上，对不上的丢掉，结论照存，也不为补标重发。重写成功选了零章，就清掉上一版重点；重写失败或被停止，原结论和原重点继续有效。补块改了章节，旧重点不再显示；还有缺块时不标，补齐后由新结论重新选，这次结论失败或被停止时，补好的章节保留，旧重点不套上去。
- 已有概览不为补重点另发请求。换字幕后旧重点随原概览保留，标「基于旧字幕」；要新字幕的重点，按新字幕重新生成。
- 长视频分块生成：显示进度，每完成一块先显示已有的章节；部分失败时保留成功的部分，可以只补失败的块。章节写完而结论没写出来时，可以只重写结论：复用已保存、依据对得上的章节，不重跑分块；依据不明的旧概览不能靠重写结论变成依据字幕。
- 可以停止和重新生成。界面写明：已经发出的请求可能已经计费，重新生成会再调一次模型。重新生成中途停下或失败，不覆盖原来那份概览，章节写完、停在写结论这一步也一样：原来的章节、结论和重点照常显示和导出，这次付过费的进度另存，可以接着写结论，也可以放弃。没有旧概览的首次生成，照常保留已完成的章节。
- 模型阶段失败时，已经拿到的字幕和已完成的部分都留着。
- 概览长期保存在本机，可以和笔记合成 Markdown 学习稿。保存失败时结果照样显示，并提示没存上。
- B 站：官方总结和模型生成的概览分开显示。可以只用官方总结写一句话结论，标明「依据 B 站官方总结」，不冒充通读了全部字幕（F14）。
- 没有字幕时（导入的、平台的、B 站官方总结附带的 AI 字幕都没有）：提示登录或导入字幕；YouTube 还没读取文字稿时先提示读取（F02），不算没有字幕；B 站有官方总结的，可以只用官方总结写结论；连官方总结也没有，用户点了才只用标题和简介写一句话结论，判断固定为「信息不足」，并写明只依据标题和简介。B 站视频两样都没有时，自动生成和本窗口全部生成不发请求，标出原因；YouTube 不走这两条路（F10、F13）。
- 每份结论和概览都记下实际依据，分四种：字幕、B 站官方总结、标题和简介、旧版未知（从旧备份导入、依据不明，F20）。界面按实际依据标注；只用官方总结或只用标题和简介写的结论单独标出，不显示成依据字幕的概览。

边界：YouTube 没有可读的平台官方总结，首发不承诺同等入口。

完成标准：两站一小时以上的视频能分块生成完整概览；停止、补块、只重写结论、重新生成的行为符合上面的描述，重新生成停在写结论这一步时原来的概览、结论和重点不变；重点章节的选取、失效和清除符合上面的规则；英文视频的结论和章节是中文。

### F06 引用问答

**状态**：当前已实现（B 站）；速览的提问入口、YouTube 首发待实现。

行为：

- 在速览和精读里都能针对当前视频提问，两种模式共用同一个问答抽屉和这个视频（含分 P）的本地历史。在速览里提问不切模式，不记住频道（第 6.4 节）。
- 底部的入口只打开抽屉，用户提交才发请求。有可用字幕就能问，没有概览也行；只有官方总结、没有字幕时说明原因。发送前照常核对站点已启用、模型配置和数据同意。
- 长字幕先在本机检索相关段落，再把这些段落发给模型。
- 回答带时间点和字幕原文引用，点了跳回视频。引用要落在实际发给模型的字幕范围里，原文从本机字幕里取；一条有效引用都没有时，如实说字幕里找不到依据。
- 每个问题单独回答，不带前面的问答；追问要写清对象。
- 起手问题只填进输入框，发不发由用户决定。生成中可以停，回答可以复制，历史可以删。
- 问答历史按视频保存，并记下依据的字幕。换视频后迟到的回答只回原来的记录。

边界：

- 引用校验只说明依据出自字幕，不保证模型的结论一定对。对外写「校验引用，证据不足时如实说明」，不写「不编造」。
- 不做跨视频问答，不做多轮对话上下文；用户没提问时不调模型。

完成标准：两站各问几类问题（概括、找细节、字幕里没有的），引用都能点回正确位置，找不到依据时提示正确；在速览里提问后模式和频道偏好不变，抽屉开着时自动切换后仍能撤销。

### F07 划词解释

**状态**：当前已实现（B 站）；YouTube 首发待实现。

行为：

- 在精读的字幕里选中术语、句子或概念，点「解释」，结合前后文给出好懂的说明，显示在选中文字旁边，可以关掉。
- 后点的词不被先点的回复盖掉；换视频后不出现旧视频的解释。
- 选中的文字和前后文按数据说明发给模型。

边界：不扩展成任意网页划词，不做词典和生词本；学英语的挑词在 F18。

完成标准：两站各选几处术语和长句，解释贴在原位，换视频后清空。

### F08 时间戳笔记与悬停图标

**状态**：笔记、润色和导出当前已实现（B 站）；悬停图标、YouTube 首发待实现；图标跟着控制栏显隐、YouTube 上的 `n` 键首发待验证；点图标后由 AI 总结这一刻在更新二（F17）。

行为：

- 播放器上：鼠标悬停、进度条出现时显示一个笔记图标，不带「笔记」文字；控制栏隐藏时图标也隐藏。跟着控制栏显隐首发待验证：哪个站拿不到控制栏显隐的信号，就改成鼠标在播放器上移动后显示几秒。点图标或按 `n`，记下当前时间点和这一刻的字幕；YouTube 还没读到字幕时只存时间点，不触发读取，也不润色。保存结果用图标状态或一句短提示反馈：保存中、已保存、这一刻已有笔记、已保存但没润色、失败原因。正在播广告或找不到视频时不存，并提示原因，不把广告的播放时间记成视频的时间点。
- `n` 快捷键不截获输入框里的文字，不和播放器自己的操作冲突。YouTube 上是否和站点自己的快捷键冲突，首发待验证；冲突时，YouTube 上默认关掉这个快捷键，保留站点原行为，只用图标记笔记。这项核对属于 F08，F11 移除时也要做完。
- 笔记先存原文；设置允许时再用模型润色成通顺的一句话。润色失败保留原文，不丢笔记。播放页发起的润色有频率限制，超出时只存原文。
- 概览里的金句可以一键存为笔记。
- 侧边栏里可以编辑、删除、复制、回放、跳转；看本视频或全部笔记，按正文、标题、作者搜索。
- 导出：当前范围的笔记导出成 Markdown；学习稿把概览、金句和笔记合成一份，有 B 站官方材料时带上并注明来源；章节目录和正文标题都在重点章节后写「（重点）」。
- 笔记里的链接由视频身份重新生成，能看出是哪个站、哪个视频；备份里带的链接不作为跳转依据。

边界：

- 首发没有独立的笔记本页面，从侧边栏的笔记区和导出使用（笔记本在更新二）。
- 网页不能冒充用户点图标：只认真实点击，图标被遮挡、变透明或被改样子时不响应。B 站页内小窗出现时，图标避开小窗的关闭按钮。

完成标准：两站悬停时图标出现、移开后消失，点击能存对时间点；`n` 有两种通过结果，快捷键启用时按 `n` 存对时间点，YouTube 因冲突关闭时保留站点原行为，悬停图标仍能存对时间点；在输入框里打 n 不触发；润色失败不丢笔记；导出的链接能回到正确的站、视频和时间点。

### F09 推理强度

**状态**：首发待实现。现有版本把推理压到最低，用户改不了。

行为：

- 设置页里每个用到模型的功能都能单独选推理强度：关、低、中、高。新安装全部默认关。
- 覆盖的功能：概览、一句话结论、翻译、问答、笔记润色、划词解释、解释当前画面（仅 F11 进包时）；以后新增的模型功能也一样。
- 档位是用户的意图，换服务商或地址时保留；实际生效的档位按新的服务和模型重新判断，设置页显示实际档位。
- 有的模型关不掉思考，或者不支持某一档，就用最接近的一档，并在设置页说明，例如「这个模型关不掉思考，按最低档」「这个服务的中档和高档效果相同」。用户选了「关」，实际不能变成更高的默认档。

### F10 自动生成

**状态**：总开关和「打开 B 站视频就生成概览」首发待实现；YouTube 首发不自动生成，走单视频手动生成；窗口里的 B 站视频自动排队在更新一；精华候选在更新二；挑词在更新三。

行为：

- 设置页一个总开关，新安装默认关。打开前要先完成数据同意（第 9.2 节）。设置页写明：「自动生成适用于 B 站。看 YouTube 时，请先读取当前视频的文字稿，再点『生成概览』。」
- 打开时再确认一次，写明后果：打开后，每打开一个 B 站视频，简幕会自动把它的字幕、标题、作者名和简介发给用户的模型服务，会花用户的 API 额度；随时可以关，关掉后排队中的请求立即停，已发出的收尾。
- 首发：打开 B 站视频就生成概览，不设时长门槛；外文视频同时开始翻译字幕（F04）。「打开视频」指获得焦点的 Chrome 窗口里，活动标签页加载出一个视频，包括站内换到下一个视频。后台打开的标签页，第一次真正切到前台时才算打开；窗口不在焦点上时，它的活动标签页也不算。发请求前再核对一次窗口、标签页和视频都没变。窗口里还没切过去看的 B 站标签页，由更新一的自动排队处理。
- YouTube（首发统一跳过）：走单视频手动生成（F02、F05）。打开视频、切到前台或打开侧边栏，都不为自动生成取字幕，也不连带启动 F04 的自动翻译；已有缓存或导入字幕的视频也一样。缺材料不发模型请求，不记一次失败。不能从「用户曾经开过面板」推导出后台读取的许可。
- 更新一：窗口里开着的 B 站视频自动排队生成，和标签页粗筛一起上线（F16）。YouTube 受 F02 的读取边界约束，这次更新不默认恢复对后台 YouTube 标签页的读取。
- 更新二：精读时自动准备精华笔记候选（F17）。
- 更新三：学英语时自动挑词；按标题、简介、频道判断视频是学英语还是拿信息（F18）。
- 概览和翻译分别判断。已经有概览的视频不再自动生成概览：基于旧字幕的、不完整的也算有，要重做由用户点重新生成或补块（F05）。缺重点章节不算没有概览，不为补重点自动发请求。已经有译文的不再自动翻译。已有概览、还没有译文的外文视频，照样自动翻译（F04）。两者各自记下自动试过的视频，同一次浏览器会话里不重复自动试。站点已启用、已同意、模型配置齐、不在额度用完的暂停里，这几条两者共用。
- 同一视频的等价请求在侧边栏、卡片和自动生成之间只跑一份（F12）。
- 自动生成失败时如实标出，之后不再自动重试这个视频（偶发失败在次数上限内的自动重发见第 9.4 节）；服务商报额度用完时停下整个队列。

边界：B 站短视频也会生成，但界面仍按第 6.2 节进精读，不把概览推到最前。网页不能触发自动生成，生不生成只由扩展按规则判断。

完成标准：开关关着时，打开视频不发任何模型请求；打开后，焦点窗口里的前台 B 站视频生成一次且只一次，后台标签页和不在焦点上的窗口不生成，后台标签页第一次切到前台时生成；已有概览、没有译文的外文视频只补翻译；关掉开关后排队的请求不再发出；开着开关打开 YouTube 视频，不取字幕、不发模型请求、不记失败。

### F11 画面分析

把视频画面截下来交给能看图的模型，读出字幕里没有的内容：幻灯片、代码、图表等。三种用法分三个版本上线。

**状态**：

- 解释当前画面：首发待验证，在第 11 步实现和验证。「画面验证构建」指显式打开 `FEATURE_FRAME_EXPLAIN` 的本机构建，「发行构建」指默认关闭、代码被裁出包的构建，两者用同一份产品代码。先在画面验证构建里确认两站普通视频能唯一找到主视频、读出与屏幕一致的当前帧，并能在截取前主动识别加密播放，再接模型和两个入口。满足用法一里的拒绝条件和本节的完成标准才打开发行开关，并在最终候选包回归。
- 画面信息并入概览：更新一。
- 笔记里插关键画面：更新二。
- 画面验证失败或缺少关键证据：首发移除全部画面功能，不拖首发。模型选择、能力探测、消息路由、提示词、首次启用说明、同意说明和 README 的截图、演示 GIF 都随开关处理，发布前逐项核对。解释当前画面最早在更新一重新评估；另外两种用法仍按上面的计划和各自的前提推进，不承诺在更新一全部上线。

用法一：解释当前画面

- 入口两个：精读侧边栏里一个按钮；播放器鼠标悬停时出现的图标，和笔记图标并排。
- 点一下，截当前这一帧，连同前后几句字幕，交给画面分析选的模型，在侧边栏显示解释：画面上写了什么，和正在讲的内容是什么关系，看不清的地方如实说。YouTube 还没读到字幕时不带字幕，不触发读取，并提示先读取文字稿才有前后字幕。
- 从播放器图标点的，先打开侧边栏，再截帧、调模型，结果放在侧边栏。浏览器支持由页面上的真实点击打开侧边栏，要验证的是从这次点击到打开侧边栏的具体调用链，首发待验证；打不开时，页面上提示「结果在侧边栏，点简幕图标查看」，结果留到侧边栏打开。
- 只截视频画面本身，不带弹幕、控制栏和页面上的其他内容。
- 这些情况不截、不发请求，并说明原因：找不到视频、画面还没加载好、内容受版权保护（加密播放）、标签页不在前台、正在播广告、截帧时视频已经换了、所选模型不能看图。加密播放由简幕主动识别并拦下，不靠截出来的是不是黑帧来判断；保护状态无法可靠判断时同样拒绝。
- 截图只用于这一次请求，不存在本机，画面验证构建也一样。解释和划词解释一样显示在侧边栏，不长期保存。
- 不为画面分析申请访问所有网站的权限。

用法二：画面信息并入概览（更新一）

- 在画面明显变化处截几帧，把幻灯片、图表的要点并进章节；字幕很少的视频也能出概览。
- 截图只能来自正在播放的画面。怎么拿到还没播过的部分，在更新一之前单独评估；不为此下载视频，不加必需权限。

用法三：笔记里插关键画面（更新二）

- 记笔记或挑精华时附上当时的画面。截图存在本机，存多少、进不进备份，在更新二之前定。

模型：

- 只有能看图的模型能用。设置页给画面分析单独选模型；不另配服务商，在当前服务商里选能看图的模型。所选模型不能看图时提示换一个。
- 不做本地 OCR。

数据：截图是新的一类发送内容。什么时候写进数据说明、哪些用法上线前要重新同意，见第 9.2 节。第一次截帧之前，先完成覆盖读取当前单帧的启用确认（F22）。第一次用画面验证构建向真实模型发截图之前，另外完成覆盖截图的数据同意。仅 F11 进包时，方案第 8 节关于复制和发送给模型的审阅要明确覆盖当前单帧和相邻字幕。

完成标准：量化标准见方案第 4.5 节。打开发行开关时：两站普通视频截出的画面和屏幕一致，不是黑帧或旧帧；幻灯片和代码样本上的文字模型能读对；受保护内容一律拦下；用法一的拒绝条件逐项核对，包括找不到视频、广告、后台标签页、视频已换、画面未就绪和模型不能看图，找不到视频和广告分开提示；截帧不明显影响播放。对照屏幕时用产品内容脚本的输出，不为验证给发行构建新增主世界脚本。

### F12 任务、取消与结果恢复

**状态**：当前已实现（B 站）；按请求等价复用任务、两站贯通首发待实现，由端到端测试覆盖。

- 显示进行中的任务、进度、成功结果、失败原因和停止状态。
- 只有等价的请求才复用已有任务。等价指：同一个视频、同一份依据（同一版字幕、官方总结或标题和简介，F05）、相同的功能输入（问题、选中的文字、目标语言、画面时间等）、相同的生成配置（服务地址、模型、推理强度、提示词版本）。等价的请求接上已有任务，不另发一次。任务开始时定下所用的模型配置，之后改设置不影响它。
- 不等价的请求按功能处理：概览、结论、翻译这几种，同一视频同一时间各只跑一个，用户再发起时提示已有任务在跑，可以先停掉旧的再发；自动生成和批量任务遇到这种情况跳过这一个，并标出原因，不排队。问答、划词解释、解释当前画面，不同的请求可以同时跑。
- 两个任务写同一份结果时（例如概览和只重写结论），各写各的部分，较早的任务不覆盖较新的结果。重点章节属于结论这一部分。单独重写结论时章节已经变了，这次结果不写入。
- 关掉侧边栏不等于取消。概览和问答在后台跑完并保存；翻译按 F04 的规则收尾；本窗口全部生成按 F13，稍后再看粗筛按 F15。
- 一个页面关闭，只停它自己发起、别处没在用的部分；别的页面、卡片或自动生成还在用的等价请求照常跑完。
- 重新打开侧边栏能看到还在跑的任务和它属于哪个视频，并能停止。
- 取消后不再发新的排队请求。后台被浏览器中断时明确标出，不悄悄重新发起收费请求。
- 「清除全部数据」之后，旧任务不能把已清除的资料写回来。
- 不承诺浏览器崩溃后无损恢复所有在途请求。

完成标准：关面板、重开、取消、后台中断、清除数据这几种情况，在两站都按上面的规则收尾，并有端到端测试覆盖。

完成标准：窗口里混开两站视频（含重复的、分 P 的、YouTube 未启用时的）时，清点数量正确，确认前不向平台读取、不发模型请求，YouTube 条目不计入任务数和费用，整批不读 YouTube 字幕；确认后逐个读取、有间隔，被限流就停；停止后不再发；中途关掉侧边栏再打开，能接上进度。

### F19 AI 服务与模型设置

**状态**：当前已实现；网关兼容、画面分析模型（仅 F11 进包时）、测试连接的费用说明、设置页显示版本号和隐私政策、反馈链接首发待实现；记住密钥在设置移植后用独立功能 PR 加入，发布版带不带由开发者本人定（方案第 12 节）；部分预设服务商的端点首发待验证，跑不通的从预设里拿掉。

行为：

- 用户自带模型服务和 API 密钥，支持三种协议：OpenAI 兼容、OpenAI Responses、Anthropic。
- 新安装默认用海外服务预设；设置页有国内、海外两个快捷选择，还有常见服务的预设和自定义地址。地址只认 https，本机地址也一样。
- 按功能另选模型，留空用默认模型。按功能选的模型属于当前服务商和地址，换服务商或地址域名时清空，免得密钥发错地方。仅 F11 进包时，首发加「画面分析」一项。
- 每个功能的推理强度（F09）和自动生成总开关（F10）也在设置页。
- 拉取模型列表、测试连接、测试全部模型。测试也可能产生费用，界面写明。
- API 密钥默认只存在浏览器的会话存储：浏览器重启、扩展停用、重新加载或更新后要重新填，可以单独删除。用户可以主动勾选「在这台电脑上记住密钥」（默认不勾）并保存：密钥以未加密形式存在本机扩展存储，重启后还能用，保存到取消勾选、清除密钥或清除全部数据为止，不进备份，不同步。这是单独的选择，不沿用 AI 发送的数据同意；写入前先把本机存储限制为只有扩展自己能读，设不上就不存，会话里的密钥照常能用。发布版带不带这个选项由开发者本人定（方案第 12 节），带上时按方案第 7.4 节如实写未加密，不带就只提供会话模式。
- 没有完成数据同意之前，不发任何 AI 请求，包括拉模型列表和测试连接。
- 提示词内置，按速览、精读、学英语分别重写；不开放自定义提示词。不加入 http 本地服务预设，不提供免费额度。
- 首发要兼容：强制返回流式（SSE）的模型网关；不接受 JSON 输出格式参数的网关。预设里还没在真实浏览器里跑过的服务商端点，首发待验证，跑不通的从预设里拿掉，用户仍可以填自定义地址。国内预设现在的默认模型名，服务商仍然接受，但对应的旧模型已经退役，请求改由新模型处理；首发改用服务商现行的名称，能不能看图用真实密钥核对。
- 报错统一写成「原因、影响、下一步」三段，不把同意问题、权限问题误报成密钥错误。
- 设置页显示版本号、隐私政策链接和反馈链接。

完成标准：国内、海外两个快捷预设在真实 Chrome 里跑通概览、问答、翻译和解释；模拟环境覆盖强制流式和不收 JSON 格式参数的网关；未同意时没有任何 AI 请求发出。

  - 旧备份没有重点章节，不推断、不回填、不调模型。
  - 旧的判断档位：「值得看完整视频」「可以跳过」「信息不足」换成新四档里对应的推荐看、可跳过、信息不足；「看概览就够」保留原判断和理由，不硬套进新四档，界面照旧显示这一档，粗筛分组时单列在四档之外；用户重新生成结论后才用新档位。字段怎么转见[架构设计](architecture.md)第 7.6 节。
- 不写自动迁移：发布版是一个新的扩展，现有版本的资料由用户从旧版导出备份、在新版导入。回归测试用照旧格式造的样例，不用真实资料。
- 「清除缓存」和「清除全部数据」含义分开：
  - 清缓存只清不花额度就能重新取回的东西：字幕和视频信息的缓存、官方总结、粗筛读到的列表、记下的模型能力。花过额度的结果和用户自己的资料都留着：概览和粗筛写的结论、译文、笔记、问答、导入的字幕、频道偏好，以及设置。现有版本清缓存时连译文一起清，首发改成保留。
  - 清全部删掉所有本地资料和设置。
  - 清除时，开着的侧边栏、卡片和粗筛页立即清掉旧内容；清除后旧任务不能把资料写回来。
- 撤销站点访问权限，不自动删除已经存下的资料。卸载扩展时浏览器会删掉扩展本地数据，要长期留的资料由用户先导出。

完成标准：新版导出再导入不重复、不丢；两份旧格式样例（现有版本导出的、Digest for Bilibili 风格的）能导入，跳过计数正确；清除期间正在跑的任务不把资料写回。

### F21 外观与界面

**状态**：主题和字号当前已实现；界面和图标重新设计首发待实现。

- 三套主题：宣纸墨青、石墨靛蓝、暖岩赭石；明暗可选跟随系统、浅色、深色；三档界面字号。改了立即生效，不用重新授权模型服务。
- 首发重新设计界面和图标：侧边栏按模式重排（第 6 节）；图标从已有候选里挑，提供 PNG，不像 B 站的小电视，也不像 YouTube 的播放按钮。
- 每个页面都有加载、空内容、没权限、缺设置、出错、部分成功几种状态，错误提示写出下一步。
- 文字对比度在浅色和深色下达到 WCAG AA；键盘能操作，焦点看得见。

完成标准：最终界面在三套主题、两种明暗、三档字号下重新做回归测试，不用旧版本的结果代替。

### F22 首次启用与站点权限

**状态**：B 站站点权限当前已实现；首次启用确认、YouTube 可选权限、统一授权管理、安装或更新后自动补上连接首发待实现；从侧边栏启用 YouTube 首发待验证。

首次启用确认：

- 安装后，简幕先不读任何视频数据。第一次打开侧边栏或设置页时，在扩展自己的页面里说明：
  - 会读取什么：视频信息（标题、作者和频道、时长、简介）；字幕（YouTube 上只在用户点读取时读观看页文字稿面板里显示的内容；第 2 档通过时，写明用户点「打开 YouTube 文字稿并读取」后简幕打开一次面板；代换语言通过时，写明用户选定目标后简幕切换一次面板语言，F02）；B 站官方总结和 UP 主分段；观看状态（播放、暂停、累计播放时长）；本窗口全部生成时，已授权网站标签页的地址和标题；打开粗筛并点读取时，B 站稍后再看列表；开启 F11 的产品构建（含画面验证构建）里，用户点击后读取当前单帧，用于解释画面。
  - 用来做什么：在侧边栏和卡片里显示；按时长、频道和播放情况选模式（第 6 节）；作为之后生成和问答的材料。
  - 本机存什么：字幕和视频信息的缓存，有期限和条数上限；粗筛读到的列表和官方总结，有期限；这两类都可以在设置页清除（F20）。用户保存的概览、问答、笔记和译文长期留在本机，保存到用户删除为止。
- 用户点「启用简幕」后才开始读取。确认前，侧边栏只显示这份说明；播放页卡片和播放器图标不出现；内容脚本不读页面上的视频信息、不计播放时长；后台不看标签页地址、不取字幕和官方总结。
- 只确认一次，不每个视频弹窗。读取的内容或用途有实质变化时，按第 9.2 节同样的规则更新说明、重新确认。「清除全部数据」会清掉这次确认，之后要重新确认。
- 开启 F11 的产品构建，含画面验证构建，在第一次截帧之前完成覆盖这一用途的启用确认，沿用这里的确认机制，不每次截帧都弹窗。确认过不含当前单帧的旧说明的人，算实质变化，要重新确认：说明只列新增的内容，确认之前按未确认处理。第一次发图之前另查数据同意（第 9.2 节）。
- 这一步和另外两件事分开管理，互不代替：浏览器的站点授权（下面的 YouTube 和 AI 服务地址）决定简幕能不能访问那个网站；首次启用确认决定简幕能不能在本机读取和处理这些内容；数据同意（第 9.2 节）决定能不能把内容发给模型服务。点了「启用简幕」不等于同意发给模型。

站点权限：

- B 站：安装时就有访问权限，完成首次启用确认后即可用。
- YouTube：安装时不申请。用户在设置页「站点」一节点「在 YouTube 上启用」时，浏览器询问是否允许访问 www.youtube.com。拒绝或之后收回，B 站照常用。启用之前简幕看不到 YouTube 标签页的地址，所以侧边栏不判断当前页是不是 YouTube，只在认不出的页面上附一个「在 YouTube 上启用」按钮（F01）。能否在侧边栏里直接弹出授权首发待验证，不行就引导到设置页。
- 启用 YouTube 只是让简幕在观看页读取视频信息和观看状态，在用户点读取时读文字稿，本窗口全部生成时看已授权标签页的地址和标题，并加上播放器图标；不会因此调模型，自动生成首发也不读 YouTube 字幕（F10）。
- 停用 YouTube 或收回权限后，已打开的 YouTube 页面停止读取、撤掉界面。
- AI 服务地址：用户保存时只为那一个地址申请。换了地址再保存，收回旧地址的权限，但不能收掉 YouTube 和 B 站的权限。现有版本的收回其实没有成功过（方案第 2.1 节），首发要修好。
- 扩展只看得到已授权网站（B 站、启用了的 YouTube、填了的 AI 服务地址）标签页的地址和标题。
- 安装或更新前已经打开的视频页，按 F01 自动补上连接，补不上就提示刷新。
- 不申请访问所有网站的权限。完整的权限清单和不申请哪些权限，见方案第 7.1 节。

完成标准：首次启用确认前，打开两站视频页、侧边栏和设置页，扩展不读视频数据，也不向两站发请求；点「清除全部数据」后回到未启用状态，重新点「启用简幕」后恢复；启用说明有实质变化时旧确认失效，重新确认后恢复；F11 不进包时说明里没有当前单帧；启用、拒绝、收回、停用、浏览器重启、扩展更新几种情况下，权限状态和界面一致；保存 AI 设置不影响 YouTube 授权。

## 8. 关键使用流程

### 8.1 第一次使用

照 README 安装 → 打开侧边栏，读首次启用说明，点「启用简幕」→ 登录 B 站，打开一个视频，先看字幕和官方总结（不用密钥）→ 想在 YouTube 上用：在设置页点「在 YouTube 上启用」（侧边栏认不出页面时也有这个按钮），浏览器询问时允许 → 想用 AI：在设置页选快捷预设、填密钥、读数据说明并勾选同意、保存并授权 → 可选：调各功能的推理强度，打开自动生成（首发只处理 B 站，F10）。

首次启用、站点授权和 AI 同意是三件事，各管各的（F22、第 9.2 节）：启用简幕只在本机读取和处理，不调模型；只启用 YouTube 也不会调模型。

### 8.2 判断一个长视频

打开长视频 → 侧边栏进速览：B 站先显示官方总结，已有概览就直接显示；开了自动生成就开始生成，没开就点「生成概览」。YouTube 按提示读取文字稿，显示实际轨道后点「生成概览」（F02、F10）→ 看一句话结论和章节，重点章节已经标出来，展开感兴趣的章节读这一段字幕，有疑问就在底部提问，不用切模式 → 不值得看就关掉；值得看就播放，或者点章节跳过去 → 连续播放满 1 分钟，自动切到精读。

### 8.3 精读

字幕跟着播放高亮 → 不懂的词句划词解释；画面上有幻灯片或代码就点「解释当前画面」（仅 F11 进包时）→ 随时提问，点引用核对原文 → 悬停点图标或按 `n` 记笔记 → 看完导出笔记或学习稿。更新二起：看完挑精华，收进笔记本。

### 8.4 一个窗口的视频

首发：点「本窗口全部生成」，确认数量和费用后批量生成 B 站视频的概览，再逐个切过去看结论。YouTube 标签页标「需逐个打开」，本批跳过，用户自己切过去后按单视频流程读取和生成（F13）。更新一：打开标签页粗筛，按四档分组看一句话结论，可跳过的一键关掉（F16）。

### 8.5 稍后再看

设置页打开粗筛页 → 读取列表 → 第一步取官方总结 → 需要时第二步写结论 → 按分组挑出要看的，导出清单。

### 8.6 英文视频

为了拿信息：和中文视频一样走速览和精读，结论和章节是中文，字幕中英对照。为了学英语（更新三）：切到学英语，逐句听，收藏 AI 挑出的词和表达。

### 8.7 没有字幕或取不到

按原因提示（没有字幕、空文件、要登录、被限流、网络错误、视频不可用；YouTube 认不出原因时报暂时无法读取）→ 用户可以重试、登录或导入字幕文件。YouTube 面板没打开时提示用户打开，这是待用户操作，不算失败。不自动换别的方式反复尝试，不转写音频。

### 8.8 切换视频、站点或字幕

界面立即换到新视频 → 旧请求的结果只回到它所属的记录 → 新视频载入自己的资料和模式。换了字幕时，依据旧字幕的结果标成「基于旧字幕」。

### 8.9 从现有版本搬资料

在现有版本或 Digest for Bilibili 的设置页导出备份 → 在新版简幕的设置页导入 → 看导入结果里跳过了几条、为什么 → 重新填密钥和设置。

## 9. 隐私、费用与数据同意

### 9.1 隐私原则

- 开发者没有接收用户内容的服务器，不要账号，不放广告和分析 SDK，不加载远程代码。
- 只在本机处理的读取也要先说清用途、经用户确认：首次启用确认前不读任何视频数据（F22）。
- 首次启用确认、站点访问权限、「把内容发给 AI 服务」的同意三者分开处理。启用后不勾 AI 同意，字幕和官方总结照样能读，只在本机处理。
- 发给模型的只有数据说明里列出的、完成当前功能需要的内容：
  - 视频的字幕：平台的人工或自动字幕，或者用户导入的字幕文件；
  - 标题、作者名（UP 主或频道名）、简介、时长；B 站视频还可能有官方总结；
  - 用户选中的文字和提的问题；
  - 点「解释当前画面」时，当前这一帧的截图和前后几句字幕（仅 F11 进包时）。
- 平台的登录 Cookie、登录凭证和平台返回的字幕地址不发给模型。密钥不进入网页、日志和备份。
- 扩展只看得到已授权网站标签页的地址和标题。本窗口全部生成会读取它们，在数据说明和隐私政策里写明；稍后再看列表同样写明。

### 9.2 数据同意

这里的同意只管「把内容发给模型服务」。本机读取的说明和确认是另一件事（F22 首次启用确认），两者分开记录。

更新规则：

- 发给模型的内容类别、使用目的、接收方、发送的触发方式或范围有实质变化时，同步更新数据说明。
- 变化超出了用户原来同意的范围，先请用户重新同意，再启用变化后的行为。同一类内容从「点了才发」变成自动发送或批量发送，也算超出。
- 只改文字、不改实质的，不要求重新同意。
- 开发期间也一样：开发构建里已经有人同意过，之后再扩大范围，就要让旧的同意失效。版本号怎么记、怎么让旧同意失效，见方案第 7.3 节。

首发的数据说明写清三类变化：

1. **两个站**：YouTube 视频的字幕、标题、频道名和简介，和 B 站同样处理；首发只在用户点按钮时发送。
2. **画面截图**：点「解释当前画面」时，发送当前帧和前后几句字幕。首发移除画面功能时（F11），这一项不写进首发说明，等画面功能上线时按上面的规则加上，并请用户重新同意。
3. **自动发送**：打开自动生成后，每打开一个 B 站视频就自动发送字幕、标题、作者名和简介。YouTube 视频首发不自动发送。说明里现有的「这些请求只在你点按钮时发出」要改成：「没打开自动生成时，只在你点按钮时发出；打开后，每打开一个 B 站视频就会自动发送。YouTube 视频只在你点按钮时发出。」

发布版是一个新扩展，首发对所有人都是第一次同意。以后数据说明再更新时，界面要说清这次多了什么，和「从没同意过」分开提示，不误报成密钥问题。

首发之后，按上面的规则逐项看：

- 更新一的窗口视频自动排队：自动发送的范围从前台打开的 B 站视频扩到窗口里开着的 B 站视频，上线前更新说明并请用户重新同意；YouTube 不默认跟着扩大（F10、F16）。标签页粗筛按它实际发送的内容和触发方式对照首发说明，有实质变化就同样处理。
- 更新一的画面信息并入概览：生成概览时自动发送多张截图，截图从点了才发变成自动发，上线前重新同意。
- 更新二精读时自动准备精华候选、更新三学英语时自动挑词和判断视频类型：自动发送多了新用途，超出原来同意范围的，上线前重新同意。
- 更新三如果把用户的英语水平发给模型：这是新的一类内容，上线前更新说明并重新同意。

设置页的数据说明、隐私政策和 README 三处保持一致，改一处就同步另外两处。

### 9.3 隐私政策

- 地址用公开仓库里的 `PRIVACY.md`，不另建网站。这份文件在发布准备阶段按首发的实际行为新写（方案第 7.4 节），写好后再从这里加链接。
- 骨架可以先写。登录状态、是否另发平台请求、请求由什么动作触发，等第 10 步「路线实机通过」后定稿。「扩展不读取 Cookie 内容」和「浏览器是否随请求带上登录状态」分开交代。
- 首发前补上联系方式，删掉「尚未发布的开发版」之类的说法，按两站和新存储重写；接收方列出设置页预设的服务商，附各自隐私政策的链接。
- 现有政策里「换地址后收回旧地址权限」的承诺实际没做到（方案第 2.1 节）。首发要修好，在实机上验证以后才写进政策（F22，方案第 7.2 节）。

### 9.4 费用

- 费用由用户选的服务、模型、推理强度、视频长度、翻译量和重试决定。不承诺「完全免费」或统一的费用。
- 花额度的操作开始前说清楚：批量生成和粗筛先说明数量，混开两站时 YouTube 条目不计入（F13）；自动生成开关旁写明后果；推理强度旁写明越高越贵。
- 关掉页面、取消、超时、失败都不保证服务商不计费。取消和后台中断后不自动重发。服务限流、输出被截断、超时或连接中断这类偶发失败，会在次数上限内自动重发，重发的请求也可能计费。等价的请求还在途时合并成一份（F12），但重试和重新生成仍可能再次计费。

## 10. 非功能要求

- **归属正确**：站点、视频、分 P、字幕轨和字幕版本，在读取、生成、保存、回放、导出中始终一致。
- **可靠**：部分失败保留已完成的结果；取消立即挡住新请求；后台中断明确标出；清除后不被旧任务写回。
- **安全**：网页不能冒充用户触发花钱的操作；页面传来的消息一律按不可信输入核对站点和视频；密钥不进入网页、日志、备份和其他网站。
- **不打扰看视频**：不明显拖慢播放页，不干扰播放器、评论区、顶栏和全屏；改动前后用性能基线对照。和沉浸式翻译同时安装时，两边都正常。
- **好用**：日常使用不需要手动取 Cookie 或登录凭证，不需要打开开发者控制台。报错写成「原因、影响、下一步」。
- **好维护**：站点差异集中在站点适配层，概览、问答、任务和存储两站共用；代码按两站、三种模式、笔记本、粗筛、画面分析拆模块，改用 TypeScript 加一个轻量构建步骤。细节见[架构设计](architecture.md)。
- **合规**：
  - 公开的代码注释和文档只按能力描述平台接口（例如「读取字幕轨」「读取官方总结」），不写成接口文档。
