# 简幕产品需求说明（PRD）

2026年11月26日更新。

本文写简幕做什么、为谁做、分几版发、每一步做到哪里算完，以及几条不能破的规矩。代码怎么组织、按什么顺序搭，见[架构设计](architecture.md)。

## 1. 结论

**给谁用**：首先是开发者本人，B 站和 YouTube 都常看，长视频多，一个窗口常开几十个标签页；其次是有同样习惯、愿意用自己 API 密钥的中文用户。

**解决什么**：几分钟内判断一个长视频值不值得看、重点看哪段；决定看了，再陪着精读。

**路线**：

| 步 | 做什么 | 做完的标准 |
| --- | --- | --- |
| 1 | 在新版里做「打开就出结论」（F10） | 打开开关后，B 站上超过设定时长的视频一打开就生成，结论显示在播放页卡片上，不用点 |
| 2 | 换到新版：开发者本人停用旧版，用新版日用 B 站（[架构设计](architecture.md)第 12 节第 9 步） | 只有两条：概览和问答在真实 B 站页面上不比旧版差；「打开就出结论」能用。B 站付费判断照常核对一次，不算门槛；旧版资料不迁移（开发者本人 2026-11-17 定），旧格式备份的读取靠自造样例的测试保证 |
| 3 | 做 YouTube：两站一个侧边栏，先在开发者本人的日用包里用起来（开发者本人 2026-11-19 定，先做 YouTube 再首发） | YouTube 真实页面验证通过；开发者本人看两站都用简幕 |
| 4 | 首发：在 GitHub 发两站都支持的版本 | 下面的首发范围都做完；陌生人照 README 几分钟能装上，并在 B 站和 YouTube 都走通主流程 |
| 4a | 上架 Chrome 应用商店（开发者本人 2026-11-20 定，排在 GitHub 首发之后） | 商店里装得上，和 GitHub 版是同一个扩展身份；GitHub 首发不等商店审核 |
| 5 | 更新一、二、三 | 小步快发，某一项没准备好就顺延到下一次，不拖住整次更新 |

主流程指：打开一个视频，读到平台字幕，看到结论和章节，做引用问答。单靠导入字幕不算。

**首发范围（两站）**：

- B 站上现有的功能（F01–F08、F12–F15、F19–F21），含已经做完的本窗口全部生成和稍后再看粗筛。
- YouTube：认出观看页、读字幕，概览、结论、问答、笔记、翻译和整理字幕照常能用；站点权限按需申请（F22）。
- 新加：速读和精读两种模式，以及自动切换（第 6 节）；打开就出结论（F10）；解释当前画面（F11）；推理强度可调（F09）；悬停才出现的笔记图标（F08）。
- 发布必需项：首次启用确认（F22）、隐私政策、README（演示、安装和更新步骤、中英文）、Releases 里的 zip 和校验值、商标检索、和商店那边一致的扩展身份（第 3 节）。

**成功标准**：首发看第 4 步那两条，「两站都用」看第 3 步。想要尽量多的 GitHub 星，不定数字；扩展里不加统计，日用与否由开发者本人判断。

发版和对外宣传，每次都要开发者本人同意。

## 2. 现状和要解决的问题

**现状**：旧的私有版开发者本人几乎每天都用，最常用概览和章节、问答。最烦两件事：YouTube 上用不了；每次都要手动点开、点生成，再干等结果。新版在这个仓库里重写，开发者本人 2026-11-17 起用它日用 B 站；首发要带的新功能（第 1 节）都已经做进主线，还没发版，发布必需项还没做完。

**要解决的问题**（依据只有开发者本人的使用习惯，没有其他用户数据）：

1. 长视频要先看结论和章节，再翻字幕，然后决定看不看；结论要来得快，打开就该看到。
2. 短视频不需要概览，主动弹出只会打扰。
3. 标签页太多，稍后再看也要再筛一遍，挨个点开太慢。
4. 两个站分在两套工具里。B 站约占看视频时间的三分之二，YouTube 约占三分之一。
5. 外语视频一半为了拿一手信息，要所选语言（他自己选中文）的结论和中英对照；一半为了学英语。
6. 记笔记太麻烦，希望 AI 来写，或给出候选一键收藏。
7. 自己愿意多用强模型和自动功能，新用户的默认值仍要省钱。
8. 回答要能回到视频的时间点和字幕原文，自己核对。

**卖点**只讲三条：两个站一个工具；打开就出结论，一个窗口的视频一次判断完；用自己的模型，每个功能单独调推理强度。B 站官方总结照常显示，简幕再补上结论和章节。代价照实说：自备密钥、费用自担，手动安装和更新。

## 3. 形态

- Chrome 扩展（Manifest V3）。在 GitHub Releases 发 zip，用户解压后在开发者模式下加载。GitHub 首发以后再上架 Chrome 应用商店，首发不等商店审核（开发者本人 2026-11-20 定，原来是暂不上架）；Edge 不是前提。
- 更新靠用户解压新版覆盖同一个文件夹再重新加载。构建带固定的 `key`，扩展身份从第一个公开版本起不变；商店版和 GitHub 版要是同一个扩展身份，不然从一边换到另一边资料接不上，所以身份在 GitHub 首发之前就在商店后台定下来了：2026-11-20 传了一份不公开的草稿，清单的 `key` 换成了商店给的公钥，签名用的私钥在商店那边，项目里不用保管任何私钥；覆盖更新后身份和本机资料要能保留，没验证通过不发布。
- 没有开发者后端，不要账号，不放广告和统计，不加载远程代码，不做变现。用户自带 API 密钥，资料存在本机。新安装默认省钱：自动功能和推理强度都关。
- 点工具栏上的简幕图标打开侧边栏；右键点它，菜单里有简幕自己的三项：「稍后再看粗筛」在新标签页打开粗筛页，「在视频右侧显示总结卡片」和「打开视频就出结论（花 API 额度）」两个勾选项是短标题，各对应设置页上的一个开关，是同一项设置，后者的标题里写明花 API 额度。没确认启用时两个勾选项不改设置，改为打开设置页；打开后者和设置页一样要先同意数据说明，没同意时也改为打开设置页。
- 底线：资料始终归属正确的视频、分 P 和字幕版本；部分失败保留已完成的；网页不能冒充用户触发花钱的操作；不拖慢播放页，和沉浸式翻译同时装也正常；报错写成「原因、影响、下一步」；模型服务报错时自己说明了原因的，下面另附一行默认收着的「服务的原话」，只当纯文本显示、截短，鉴权失败的不附，也不存进本机。
- 来历：从 Digest for Bilibili 0.4.6 分叉（MIT 许可），不再同步。名字、结构、界面、图标和提示词都换成自己的；有测试的纯逻辑是移植的，所以仍含它的代码。

## 4. 功能清单

「首发」指两站都支持的第一个公开版本（开发者本人 2026-11-19 定，原来首发只带 B 站）。

| 编号 | 功能 | 做什么 | 哪一版 |
| --- | --- | --- | --- |
| F01 | 视频识别与侧边栏 | 认出 B 站播放页（含分 P）和 YouTube 桌面版观看页；侧边栏跟着当前标签页和视频走，旧视频的结果不写到新视频上 | 首发 |
| F02 | 字幕获取与阅读 | 读平台字幕轨，标出语言和来源，判定不了来源时标「未确认」；原文、译文、双语三种显示，每个视频记住上次选的那种；跟着播放高亮，可搜索（原文、译文和整理后的字幕一起搜）、复制（对照时连译文一起复制）、导出 SRT；原文没有标点的段落按原始字幕的行分开显示，不加标点；失败原因分开提示。读取规矩见第 8 节 | 首发 |
| F03 | 导入字幕 | 导入 SRT、VTT 文件，平台没有字幕时备用；换了字幕，旧结果标「基于旧字幕」 | 首发 |
| F04 | 翻译与中英对照 | 用用户自己的模型分批翻译；默认显示原文，点了「译文」或「对照」才开始译，打开视频不会自己译：再打开上次选了译文或对照的视频，只显示本机已经译好的部分，没译到的照旧显示原文；点了就在后台译完，关掉侧边栏也继续，重开能接上进度，点停止、视频所在的标签页换了视频或关掉、额度用完或密钥被拒时停。平台的机器翻译字幕轨尽量不用：B 站有别的能用的轨时不列，能用的全是机器翻译时照留；YouTube 只在第 8.2 节第 8 条的情形照用 | 首发 |
| F04a | 整理字幕 | 点「整理字幕」才做（精读里，或速读里还没有概览、摆着整份字幕时）：用用户自己的模型给字幕补标点、改明显的同音错字，分批显示，点了就在后台做完（和翻译一样，关掉侧边栏也继续），能停止，按字幕版本存在本机，下次直接用；整理后的替换原文显示，能切回原始字幕，翻译仍基于原文。模型只许补标点和改同音字，不许改写、删减、合并或拆分；本机核对，去掉标点后和原文差得太多的那一段不用，照旧显示原文。不进「打开就出结论」和本窗口全部生成 | 首发 |
| F05 | 概览与一句话结论 | 所选语言（F21a）的一句话结论带四档判断：推荐看（原片有概览替代不了、分量不轻的东西，值得看完整视频）、可以看（有收获，挑重点章节看就够）、可跳过（不用看原片：内容空、大半是铺垫广告闲聊、标题许诺的没给，或者要点概览里都有了）、信息不足（缺块太多或材料判断不了）；加带时间点的章节，标出 0 到 3 个重点章节；长视频分块，部分失败保留已完成的；记下并标出实际依据（字幕、官方总结、标题和简介、旧版未知） | 首发 |
| F06 | 引用问答 | 速读和精读共用问答抽屉；回答带时间点和字幕原文，点了跳回；找不到依据如实说；每问单独回答；回答能复制，时间点写成 `[m:ss]` | 首发 |
| F07 | 划词解释 | 选中字幕（可以跨几句，也可以选译文）点「解释」，结合前后文说明，选中的超过 300 字时不给解释；同一处也能点「存笔记」，记在选中第一句的时间点。精读里能用，速读里摆着整份字幕时也能用 | 首发 |
| F08 | 时间戳笔记与悬停图标 | 悬停才出现的笔记图标和 `n` 键，记下时间点和这一刻的字幕；配好模型时保存后自动润色，播放页上记的笔记润色有次数上限；能编辑、复制、导出 Markdown，设置页能删除全部笔记；学习稿在速读的概览那里导出 | 首发 |
| F09 | 推理强度 | 每个用到模型的功能单独选关、低、中、高，新安装全关；不支持的档退到最接近的一档并说明 | 首发 |
| F09a | 推理强度的用量 | 设置页推理强度那一节，每项功能下面一行写最近一次请求服务回报的输入、输出和思考 token 数，连同当时的档位；服务没单独报思考就照实说，不估算；服务报的合计比输入加输出多时把合计也写上，不替它算成思考；不换算成钱，不做累计和历史；只留到浏览器关闭，不进备份，清缓存和清全部都清掉 | 首发 |
| F10 | 打开就出结论 | 一个开关，新安装默认关，打开前先完成数据同意。开着时，B 站和已启用的 YouTube 上超过设定时长（默认 10 分钟，可调）的视频一打开就自动生成概览，结论直接显示在播放页卡片上；外文视频不自动翻译，要译文时在侧边栏点。后台打开的标签页也排队生成，打开开关时已经开着的也算，正在看的排最前；同时最多生成两个，10 分钟最多 40 个；读平台照 B 站的限速，被限流就整批停下。已有概览的不再生成，同一视频一次会话只自动试一次，额度用完就停。YouTube 读字幕时替用户点开文字稿面板、读完关上（第 8.2 节）。以后再加：自动准备精华候选（更新二）、自动挑词（更新三） | 首发，换到新版之前做 |
| F11 | 画面分析 | 解释当前画面：截当前一帧，连同前后几句字幕交给能看图的模型来解释。只截视频本身，截图不存；找不到视频、画面没就绪、加密播放、不在前台、正在播广告、视频已换、模型不能看图时不截、不发，并说明原因。两站都有：YouTube 上只用本机已有的字幕，还没读过就只发画面，不为它去读字幕或点开文字稿（第 8.2 节第 5、6 条）。画面并入概览在更新一，笔记插画面在更新二。开发者本人在日用里用过以后 2026-11-19 定：首发带上 | 首发 |
| F12 | 任务、取消与结果恢复 | 等价请求只跑一份；关侧边栏不等于取消；取消和后台中断后不自动重发；清除后旧任务不能写回 | 首发 |
| F13 | 本窗口全部生成 | 确认数量和费用后，批量生成当前窗口里 B 站和 YouTube 视频的概览；确认前只查本机，确认后逐个读、有间隔、被限流就停。YouTube 视频经它所在的标签页读（第 8.2 节） | 首发（已做完） |
| F14 | B 站官方材料与播放页卡片 | 显示 B 站官方总结、提纲和 UP 主分段，不用配模型；B 站和 YouTube 播放页右栏的卡片显示结论和章节，展开收起跟着模式和侧边栏走（侧边栏开着时让位收起），后台标签页到前台才读（开发者本人 2026-11-19 定两站一致，原来卡片只在 B 站有） | 首发 |
| F15 | 稍后再看粗筛 | 读用户自己的稍后再看，先取官方总结（不花额度），再按需写结论，按四档分组、导出；只读，不改列表 | 首发（已做完） |
| F16 | 标签页粗筛与合集、分 P 粗筛 | 当前窗口的视频标签页一页列出结论，按四档分组，可跳过的一键关掉；也能粗筛全部分 P 或整个合集 | 更新一 |
| F17 | AI 笔记本 | 看的时候一键记下这一刻，看完挑精华；独立的笔记本页面，导出 Markdown | 更新二 |
| F18 | 学英语 | 双语字幕、逐句播放、AI 挑词和表达、收藏过的词再出现时高亮 | 更新三 |
| F19 | AI 服务与模型设置 | 支持 OpenAI 兼容、OpenAI Responses、Anthropic 三种协议；第一次配置时给国内、海外两个快捷选项，之后在服务商下拉里选 Anthropic、OpenAI、DeepSeek、Gemini、Moonshot、智谱、通义、硅基流动、OpenRouter、本机的 Ollama 或自定义，可按功能选模型；只认 https，本机地址（localhost、127.0.0.1）可以用 http，本机的服务不要密钥时可以不填；兼容强制流式和不收 JSON 格式参数的网关。密钥默认只存在浏览器会话里；第一次保存密钥时问一句要不要记在这台电脑上，默认不记，选了记住如实写明未加密，之后在设置里能改 | 首发 |
| F20 | 本地存储、备份与删除 | JSON 备份含笔记、概览、问答，以及译文和整理后的字幕（按字幕版本合并），不含密钥、设置、缓存、导入的字幕和频道偏好；能读旧版和 Digest for Bilibili 的备份，旧的「看概览就够」原样保留，粗筛时单列；清缓存只清不花额度能取回的，删除全部笔记只删笔记，清全部连首次启用确认一起清 | 首发 |
| F21 | 外观与界面 | 五套主题（开发者本人 2026-11-25 定）、明暗跟随系统、三档字号；播放页卡片的明暗跟着所在的视频页，不跟系统和设置；新界面和新图标；对比度达到 WCAG AA，键盘可操作 | 首发 |
| F21a | 语言 | 设置里选界面和模型写的内容用哪种语言：跟随浏览器（默认：浏览器界面是台湾、香港、澳门的中文或带 Hant 的写法时用繁体中文，其余中文用简体中文，别的用英文）、简体中文、繁體中文、English。界面文字和模型写的内容（结论、章节、金句、问答、划词解释、画面解释）都跟着它，视频标题不是这种语言时，结论顺带给出译名，侧边栏顶上的标题显示译名；标题是中文的（不分简繁）不给译名。翻译译成所选语言，字幕本身就是这种语言时译成另一种：选简体或繁体时中文字幕（不分简繁）译成英文，其他字幕译成所选的中文；选英文时英文字幕译成简体中文。繁体按台湾的用词写；判断档位的标识和存储不变，只换显示名；问答出处照抄字幕原文，字幕是简体就是简体。改了语言，已经生成的结果照旧显示，点重新生成才换。开发者本人 2026-11-20 定：首发做中英双语；开发者本人 2026-11-23 定：加繁体中文 | 首发 |
| F22 | 首次启用与站点权限 | 首次启用确认，规则见第 7.3 节；B 站安装时授权，YouTube 在用户点「在 YouTube 上启用」时才申请；AI 服务地址保存时只为那一个地址申请 | 首发 |
| F23 | 评论区怎么说 | 评论也是判断值不值得看的依据（开发者本人 2026-11-26 定）。生成概览时读一次正在看的视频按热度排的第一批评论（含置顶），不翻页（读取规矩见第 8.1 节和第 8.2 节第 9 条）；评论正文和点赞数放进最后写结论的那次请求，和字幕生成的章节、金句一起交给模型；不放进字幕分块的请求，免得长视频每块重发一遍。不读也不发昵称；正文里明显带联系方式之类个人信息的整条评论在本机跳过，不发也不存。评论参与四档判断，判断因为评论变了的，结论里写明「评论区普遍说……」。模型另写三样：一个口碑标签（好评居多、有争议、有人指出错误、说是标题党；评论太少时写「评论还少」，不硬总结）加一句话，显示在卡片结论下面和侧边栏「评论区」那一块的顶上；最多 4 条要点，每条挂着它依据的原评论（正文和点赞数，默认收着，点开才露，只当纯文本显示），模型只回评论序号，原文和点赞数由本机从读到的那批里取，不让模型复述；序号对不上的不显示；评论里提到的时间点能对上章节的，在那一章旁边加标记（如「评论说有误」「评论说可跳过」）。评论在提示词里当引用的材料隔开，不当指令；有人指出错误时写成「有评论指出」，不当成核实过的事实。要点和引用的原评论随概览存在本机，后来新增的评论不算进已有的概览。读不到评论（没登录、没有评论、被限流、拿不准）时照常生成概览，评论那一块说明原因，拿不准时不说成「没有评论」。补生成失败的分块、命中缓存、点开卡片都不再读评论。本窗口全部生成和稍后再看粗筛不读评论 | 先在开发者本人的日用包里用，进哪一版另定 |

## 5. 不做和以后再看

以后再看，不是承诺：问答边写边显示；上架 Edge 加载项商店；笔记导出到 Anki；音频转写（取音频等于做下载工具，隐私、权限和费用都要另算）。

不做：YouTube 稍后再看；跟读和听写；直接同步 Obsidian 或 Notion（笔记本只导出 Markdown）；不填密钥用云端模型（本机的服务不要密钥的除外）；自定义提示词；本地 OCR；主动选用平台的机器翻译字幕轨（F04 写的例外除外）；小红书、抖音和任意网页摘要；云同步、自营账号、服务器 Cookie 池；批量采集评论（F23 只读正在看的视频的第一批热评）、账号运营、改收藏；思维导图、PPT 和播客音频；跨视频的知识库问答；扩展里检查新版本。

## 6. 速读和精读

学英语模式在更新三，其余首发就有。

### 6.1 定义

模式按「此刻想从视频得到什么」分，不按视频语言分。

| 模式 | 什么时候 | 侧边栏显示什么 |
| --- | --- | --- |
| 速读 | 还没决定看不看 | 结论和章节，标出重点；每章能展开看要点和字幕；可以提问 |
| 精读 | 决定要看 | 跟着播放高亮当前章节和句子；提问、划词解释、解释画面、记笔记 |
| 学英语（更新三） | 拿视频练英语 | 双语字幕、逐句播放、挑出的词和表达 |

「速读」原来叫「速览」，和「概览」只差一个字，容易当成一个东西（开发者本人 2026-11-23 定改名）。概览是模型写出来的那份内容，速读是摆它的模式。英文一直是 Skim 和 Overview，不用改；扩展名称里的「视频速览」同一天也改成了「视频速读」（第 10 节）。

为拿信息看的英文视频也用速读和精读：结论和章节用所选语言（F21a），字幕中英对照。

### 6.2 打开视频时进哪个模式

按顺序取第一条成立的：

1. 这次观看里用户手动选过的模式。
2. 用户给这个频道选过的模式。频道在 B 站指 UP 主。
3. 按时长：不到 5 分钟进精读，不主动给概览；5 分钟及以上进速读。时长不知道时按长视频算。

### 6.3 自动切换

- 只有一种：长视频在速读里连续播放满 1 分钟，切到精读。顶部显示一行「已切到精读」，点一下回到速读；这一行看得见的时间累计满 30 秒就收起，之后要回速读得手动切。
- 本窗口的侧边栏开着时先不切：人可能正读着速读里的章节和要点，不在眼前把它换掉；侧边栏关上以后，下一次播放上报时再切，下次打开就是精读（开发者本人 2026-11-25 定，原来开着也照切，撤销回速读时展开过的章节也都收回去了）。浏览器报不出侧边栏开关的老版本（Chrome 142 之前）里照旧到点就切。
- 播放时长按实际播放累计：暂停不清零，拖动跳过的和广告不算，倍速按真实时间算，后台标签页在播也算。
- 每次观看最多自动切一次，撤销后这次不再切。换视频算新的一次；同一标签页刷新同一个视频仍算同一次，状态和累计时长接着用。
- 这次观看里手动选过模式，就不自动切。频道偏好只管打开时进哪个模式，不挡自动切换。
- 问答抽屉开着时照样计时；老版本浏览器里侧边栏开着也会到点切换，这时抽屉、草稿、焦点和在途回答都保留。
- 「已切到精读」这一行只在看得见、点得到时计时。侧边栏关着时照样计时和切换，卡片不跟着收起（第 6.5 节）。

### 6.4 手动切换和按频道记住

- 侧边栏顶部随时能切换模式。主动点一次切换就记住这个频道，以后默认进这个模式；记住时说一声，旁边给「不记」，点了只忘掉这个频道，当前模式不变。撤销自动切换、开问答抽屉、输入、发送、点引用都不算手动切换。
- 频道偏好长期存在本机，设置页可以清除；正在看的视频的模式只在本次浏览器会话里保留。

### 6.5 播放页卡片跟着模式走

B 站和 YouTube 都有卡片（F14），规矩一样（开发者本人 2026-11-19 定，原来只在 B 站有）。YouTube 上卡片插在右栏推荐视频上面，文字稿面板打开时排在面板下面；没有官方总结那一块，卡片只用本机已有的概览和结论，不为自己读字幕、不点开文字稿面板；本机还没有字幕时和 B 站一样摆「生成概览」，点了由简幕经这个视频页替用户点开文字稿读到字幕再生成（第 8.2 节第 5、6 条）；构建里没有代开文字稿时提示先在侧边栏点「读取字幕」。

- 侧边栏关着、又在速读时展开，显示结论和章节；精读和学英语时收起成一行；短视频默认收起。播满 1 分钟自动切到的精读不算，卡片照速读摆。
- 侧边栏开着时卡片让位收起，关上再回来：同一份结论和章节已经摆在侧边栏里，页面上不再摆一遍（开发者本人 2026-11-20 定，原来侧边栏开着时两边内容重复）。浏览器报不出侧边栏开关的老版本（Chrome 142 之前）里，卡片照旧只跟模式走。
- 展开时结论排在最前。章节默认只露前 5 章，点「展开全部」才全露（只多出一章时直接全露）；还没有概览时 B 站官方总结照这个规矩露，已经有概览时收成一行、点开才露。卡片上不重复视频标题，没有官方总结时不占一行去说。展开时底部一行摆按钮：能生成时摆「生成概览」，侧边栏关着时摆「打开侧边栏」，同一行没有别的主按钮时「打开侧边栏」就是主按钮。
- 收起的那一行不空着（开发者本人 2026-11-20 定，原来只有「简幕 · 总结」几个字）：本机已经读到结论时写判断档，后面是一句话结论（一行，放不下截断；开发者本人 2026-11-26 定，原来写播放到的章节）；还没有结论、只有章节时写播放到的章节（「3/7 章节名」，和侧边栏精读顶上那一条同一个写法）；旁边一个打开侧边栏的入口。浏览器没让卡片打开侧边栏时，这一行先说一句「请点工具栏上的简幕图标」，几秒后换回这一行原来写的内容；这句话只在看得见时计时，到点时标签页在后台就留着，回到前台从头数。为了写当前章节，收着时每 2 秒问一次本页的播放器播到哪，侧边栏开着、标签页不在前台、还没有章节、已经有结论时不问。侧边栏开着时卡片上不摆打开侧边栏的入口和按钮。
- 用户在这个视频里手动展开或收起过，以用户的为准，直到换下一个视频。
- 播满 1 分钟自动切到精读时，卡片不跟着收起：这时人正看着视频，右栏突然缩一下、冒出一句提示，反而打断注意力；想收起就点一下标题栏（开发者本人 2026-11-25 定，原来跟着收起，11-23 起鼠标停在卡片上时先不收）。
- 收起时不读视频数据（判断档、一句话结论和章节只用收起之前已经读到的）；后台打开的标签页第一次切到前台才读。「打开就出结论」在后台生成好的，切过去时直接显示结论。
- 展开读数据时顺带看这个视频有没有字幕，确定没有时直接说没有字幕，不摆「生成概览」，免得点了才知道（开发者本人 2026-11-26 定）。B 站登录着时列一次字幕轨，不读字幕文件，列表空着、官方总结也不会附带 AI 字幕才算没有；随后点生成时接着用这次列到的，不再列一遍。YouTube 只看播放器上已有的字幕轨列表（第 8.2 节第 7 条），播放器说这个视频能正常播、列表又是空的才算没有。列不成、拿不准时照旧摆「生成概览」。后台为「打开就出结论」问视频时长时不列字幕轨。
- 概览里有评论区的结果时（F23），展开时结论下面多一行：口碑标签加一句话。评论要点和原评论只在侧边栏，卡片不摆；收起的那一行不变。卡片不为评论另外读平台。
- 提问入口只在侧边栏，卡片不加。

### 6.6 速读里显示什么

- 有结果就直接显示：B 站官方总结和 UP 主分段，之前生成过的概览。没有结果时显示「生成概览」按钮和字幕，有字幕就能提问。
- 概览里有评论区的结果时（F23），章节下面一块「评论区」：顶上是口碑标签和一句话，下面最多 4 条要点，每条点开露出它依据的原评论；章节旁边的评论标记跟着章节走。
- 开着「打开就出结论」：超过设定时长的 B 站和 YouTube 视频一打开就生成，后台打开的标签页也排队生成、正在看的先生成，卡片和侧边栏逐块显示已完成的章节，结论写完就显示在卡片上。没到设定时长的不自动生成。设定时长调到 5 分钟以下时，短视频也会生成，但界面仍进精读。
- YouTube：还没读到字幕时，「生成概览」照样能点，点了先经视频页读字幕，读完接着生成，和卡片上的「生成概览」一样；只想看字幕的点「读取字幕」，读到后显示实际轨道（开发者本人 2026-11-25 定）。

## 7. 隐私、同意和费用

### 7.1 隐私原则

- 浏览器的站点授权、首次启用确认、发给模型的数据同意是三件事，分开记、互不代替。启用了不同意发给模型，字幕和官方总结照样能读，只在本机处理。
- 发给模型的只有当前功能需要、数据说明里列出的内容：字幕；标题、作者名、简介、时长和 B 站官方总结；用户选中的文字和问题；解释画面时的当前一帧和前后字幕；带评论功能（F23）的构建里，生成概览时还有当前视频第一批热评的正文和点赞数，不含昵称。登录 Cookie、登录凭证和平台返回的字幕地址不发。密钥不进网页、日志和备份。
- 权限从严：必需的只有 `sidePanel`、`storage`、`scripting`、`contextMenus` 和 B 站的主机；YouTube 和 AI 服务地址都按来源逐个可选申请。不申请 `tabs`、`activeTab`、`cookies`、`downloads`、`debugger`、`tabCapture`、`desktopCapture`、访问所有网站和麦克风。带密钥的请求不跟随重定向。扩展只看得到已授权网站标签页的地址和标题。

### 7.2 数据同意

这里的同意只管「把内容发给模型服务」。

- 发给模型的内容类别、用途、接收方、触发方式或范围有实质变化，同步改数据说明；超出原来同意的范围，先请用户重新同意再启用。从「点了才发」变成自动发或批量发也算超出，只改文字不算。
- 要重新同意就升版，旧同意随之失效。首发之前不再升版（开发者本人 2026-11-18 定，这期间只有他一个人在用）：开发期间用到第 5 版，那几版的条目都并进了首发的包，首发的包是第 1 版；之前的版本号都是开发期间的，对外的包不认，对所有人都是第一次同意。首发以后每次扩大范围都升版。
- 首发的数据说明要写清：打开「打开就出结论」后，B 站和 YouTube 上超过设定时长的视频一打开（后台打开的标签页也算）就自动发送字幕、标题和时长、作者名和简介；没开时只在用户点按钮时发。解释当前画面发送当前一帧和前后几句字幕。
- 评论（F23）是新增的数据类别：首发之前不升版，条目并进当前这一版。评论功能进对外的包时，数据说明、首次启用说明、同意表、`PRIVACY.md`、README 一起写上，并写明开着「打开就出结论」时评论随概览自动发送。只在日用包里开着时，按下面日用包的例外沿用。
- 以后的更新里，自动排队、自动截多帧、自动准备精华候选、自动挑词、把英语水平发给模型，都超出原来的范围，上线前升版、重新同意。
- 首发对所有人都是第一次同意。以后说明更新时，界面说清这次多了什么，不误报成密钥问题。
- 设置页的数据说明、首次启用说明、代码里的同意表、`PRIVACY.md`、README 保持一致，改一处同步其余几处。
- 例外只有开发者本人的日用包（开发者本人 2026-11-19 定）：同意过的，数据说明的条目变了照旧沿用，不停发送，侧边栏顶上一行说说明更新了，点开列出多了什么，看过就不再提；从没同意过的、清除全部数据以后照旧要同意。对外的包不适用，条目变了照上面重新同意。

### 7.3 首次启用确认

- 安装后先不读任何视频数据。第一次打开侧边栏或设置页时，在扩展自己的页面里说明，用户点「启用简幕」才开始读。确认前什么都不读、不计时，卡片和播放器图标也不出现。
- 说明里写三样：读什么（视频信息、字幕、B 站登录状态（只看是否已登录，不读 Cookie 内容）、官方总结和 UP 主分段、观看状态；本窗口全部生成时已授权网站标签页的地址和标题；打开「打开就出结论」后已授权网站各标签页的地址，包括后台打开的；粗筛时的稍后再看列表和每个视频看到哪里；点「解释当前画面」时的当前一帧；带评论功能的构建里，生成概览时当前视频的第一批热评，F23）；用来做什么（显示、定模式、作为生成和问答的材料）；本机存什么、存多久、怎么清。
- 只确认一次。读取的内容或用途有实质变化，照 7.2 节重新确认，说明只列新增的内容；首发之前同样不再升版（开发期间用到第 3 版），首发的包是第 1 版，之前的版本号都是开发期间的。「清除全部数据」会清掉确认。
- 开发者本人的日用包同样沿用（开发者本人 2026-11-19 定）：确认过的，启用说明的条目变了照旧算启用、照旧读取，多出来的条目和数据说明的一起在侧边栏那一行列出；从没确认过的、清除全部数据以后照旧要确认。对外的包不适用。

### 7.4 隐私政策

- 放在公开仓库的 `PRIVACY.md`，不另建网站，按首发的实际行为新写，不从旧版复制。
- 写清数据来源、本机读取什么（和首次启用说明一致）、什么时候发什么给模型、接收方（预设的服务商附政策链接）、存储和删除、权限、记住密钥未加密、联系方式（issue 地址和能收信的邮箱），以及 Chrome 应用商店要求的有限使用声明。中英文同步。

### 7.5 费用

- 不承诺免费或统一费用。花额度的操作开始前说清：批量处理先说数量，开关旁写明后果，推理强度旁写明越高越贵，「整理字幕」按钮旁写明要用额度、一个长视频大约和翻译一遍差不多。
- 问答每问最多送约 6 万字的字幕（短的整份送），模型说请求太长时缩到约 1.2 万字再问一次，这一次也计费；长视频每问比只送几段时更花额度；同一个视频接着问时，服务商的前缀缓存能省下一部分，但不保证。
- 模型请求同时最多 6 个：长视频的概览、翻译和批量生成更快，花的额度不变；个别服务商会因此限流。限流和过载时，服务要求等的不超过 20 秒就等一会儿自动再发一次，要等更久就直接报错；额度用完不重发。
- 关页面、取消、失败都不保证服务商不计费。取消和后台中断后不自动重发；偶发失败在次数上限内自动重发，重发也可能计费。

## 8. 平台读取的规矩

两个平台都没给过许可。开发者本人接受平台可能不同意的风险，按下面的条件做；平台或权利方正式要求停止时就停。

### 8.1 B 站

- 字幕、官方总结、UP 主分段和稍后再看只给已登录用户读：每次读取先确认登录。没登录时只读视频信息（标题、作者、时长这些公开信息），用来显示是哪个视频、按时长定模式，并提示登录或导入字幕（开发者本人 2026-11-19 定）。
- 付费和充电专属内容不读。付费状态确认不了时照读，确认是付费的才不读（开发者本人 2026-11-19 定）。
- 不下载音频或视频；不读 Cookie 值，不冒充其他客户端或设备。
- 保持低频：按站点限速；批量处理要用户先确认数量，条目之间有间隔。
- 被平台拒绝、限流或遇到人机验证就停下，按站点退避，不换方式反复试。例外只有两个：第一次被拒时重新准备一次再试；没有字幕轨，或者字幕列表、字幕文件读取失败时，用官方总结那次回复里附带的 AI 字幕，不另外向平台要字幕，注明来源；这次读取里平台拒绝过就不用。这份字幕在播放页上不一定看得到，照用（开发者本人 2026-11-18 定）。用过它的视频，离上次向平台读字幕过了 10 分钟（和官方总结重问同一个间隔）再打开时，再试一次平台字幕，读到了就换回平台字幕；站点退避期内不试（开发者本人 2026-11-19 定）。
- 评论（F23，开发者本人 2026-11-26 定）：只在生成概览时读一次正在看的视频按热度排的第一页，不翻页，不展开楼中楼，不读昵称、头像和评论者主页；登录了才读，限速、退避和其他读取一样，被拒或限流时这次概览不带评论，不另外再试。不点赞、不回复、不举报。
- 平台返回的字幕地址不落盘。
- 请求签名和读取实现公开，进公开仓库和 Releases 的 zip。不抄第三方接口文档，不带它们的文字和注释，沿用 MIT 代码的部分保留版权声明。

### 8.2 YouTube

1. 只读用户正在看的视频、平台已经在页面上给这位观众的字幕，以及第 9 条的评论。不读 Cookie 内容，不自己构造平台用来校验访问权限的数据，不冒充其他客户端或设备，不复用、重放或伪造页面的校验信息，不引起机器翻译字幕轨的请求（第 8 条里播放器自己选了机器翻译那一条的除外），不改变播放器状态（用户点时间点引起的跳转、第 8 条里替用户开关字幕除外），不绕过登录、付费、年龄或地区限制。
2. 至少读得到播放器当前给这位观众显示的那一条字幕轨的完整正文，时间轴对得上；其余的人工轨和原语言自动轨读得到就给，读不到不拦发布（开发者本人 2026-11-18 定，原来要求每条轨都读得到）。只读到当前可见的一部分不算。
3. 读到的字幕必须属于当前视频。开始读、正文返回、写缓存前都要核对，归属不了的一律丢弃。这条不满足不能发布。
4. 没有字幕、空文件、被限流、需要登录，各有能辨认的信号才报，其余报「暂时无法读取」。
5. 用户点读取、点卡片或侧边栏上的「生成概览」、打开就出结论和本窗口全部生成都可以读，读的都是开在标签页里的那个视频，经它所在的页面读（开发者本人 2026-11-19 定，要 YouTube 和 B 站一致；原来只在用户点读取时读；侧边栏的「生成概览」开发者本人 2026-11-25 定）。遇到限流或人机验证立即停下，不自动换路线。用户不用复制 Cookie、不用开发者控制台。
6. 读字幕时简幕可以替用户点开观看页的文字稿面板：只点视频简介里打开文字稿的入口；面板开着但选在章节那一页时，点文字稿那个页签。一次只点一下，点了等结果，没开就照实报，不连点、不重试；正在播广告、面板的搜索框里有字、页面上的视频对不上时不点。卡片和侧边栏上的「生成概览」、打开就出结论和本窗口全部生成从简介点开的，读完把面板关上；用户自己开着的、从章节页签切过去的不关。读字幕时不滚动（读评论按第 9 条）、不换语言。点开以后字幕是页面自己取的，简幕照旧只读页面上显示的内容（开发者本人 2026-11-19 定：先放开用户点读取时代开，后来要 YouTube 和 B 站一致，自动生成和本窗口全部生成也可以代开）。
7. 字幕标出的语言和来源（人工或自动生成）按文字稿实际显示的那一条：简幕读播放器在页面上已有的字幕轨列表来认是哪一条（卡片也用它判断这个视频有没有字幕，第 6.5 节），只读每条轨的语言、名字和是不是自动生成，不读字幕地址（第 8 条里认归属用的那几项除外），不调会改播放器的接口；认不出就标「未确认」，不猜（开发者本人 2026-11-19 定）。
8. 观看页上没有文字稿入口、播放器却有字幕的视频，简幕改读播放器自己取回来的那条字幕（开发者本人 2026-11-23 定）。只在第 6 条的代开报「页面上没有文字稿」以后才走这条路，有文字稿的视频照旧只读文字稿。字幕是播放器自己取的，简幕只接住它取回来的内容：不自己发请求，不保存、不复用请求里的校验信息；从播放器的请求里只认这是哪个视频、哪种语言、是不是自动生成、是不是机器翻译，别的不读、不存。字幕关着时，简幕可以替用户点一下播放器上的字幕按钮，读完再点一下关上；用户自己开着的不关。一次只点一下，点了等结果，没读到就照实报，不连点、不重试；正在播广告、页面上的视频对不上、播放器标着没有字幕时不点。简幕不选字幕语言：点开以后播放器显示哪一条由它自己定，取回来哪一条就用哪一条，机器翻译的也用，标出的语言按译成的那种，来源认不出就标「未确认」（开发者本人 2026-11-23 定：只要有字幕就用）。读到的字幕照第 3 条核对归属，时间超过视频时长的整份不用。这条路开发者本人 2026-11-23 起在日用包里用，2026-11-24 定：首发带上。
9. 评论（F23，开发者本人 2026-11-26 定，为此放宽了不滚动页面）：生成概览时先读页面上已经加载出来、属于当前视频的评论，够了就不滚。评论区还没加载出来、标签页在前台时，简幕可以替用户把页面滚到评论区，等页面自己加载出第一批评论，读完滚回原来的位置。只滚这一次，不往下翻更多，不换排序（页面当前不是按热门排的，照实读，不切换），不展开回复。等待时用户自己动了页面或换了视频，就不再滚回去。评论是页面自己取的，简幕不自己发请求，只读页面上显示的正文、点赞数和是否置顶，不读昵称、头像和评论者的频道。正在播广告、用户正在滚动页面或在输入框里打字、页面上的视频对不上时不滚；等不到评论就照实报，不重试，这次概览不带评论。后台标签页不滚，页面上没有已加载的评论时这次概览不带评论。本窗口全部生成不读评论。
