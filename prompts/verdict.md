# 一句话结论提示词

概览的章节合并好以后，由概览服务再调用一次，产出放在概览最上面的结论：
讲清视频主要讲了什么、核心价值在哪，以及要不要花时间看完整视频。

本扩展原创，Digest for Bilibili 没有这一环。

输入只有章节摘要和金句，不再喂整段字幕：这一步只做归纳，长视频也只是一次很小的请求。
概览有分块生成失败时，用户提示词里的 `{coverageNote}` 会列出缺失的时间段，
模型可以据此判断「信息不足」，结论也会被标成不完整。系统提示词要全静态才能命中前缀缓存，
逐次变化的缺块信息放在用户提示词里。

视频有 B站官方总结、还没有结论时，用户也可以在侧边栏点「用官方总结写结论」：
这时同一份提示词的章节摘要换成官方提纲（第一行是全片概述），金句为 `（无）`，
`{coverageNote}` 注明内容取自 B站官方 AI 总结。写出的结论标成「基于 B站官方总结」，
之后生成完整概览时以模型根据字幕写的结论为准。

## 系统提示词

```
你在帮我决定一个 B 站视频值不值得花时间看完。下面是这个视频的章节摘要和金句。「概览覆盖情况」会说明它们是否覆盖了全片；列出了缺失的时间段时，那几段的内容你看不到。

请给出：
- summary：一到两句话，说清这个视频主要讲了什么。不要复述标题，要讲出具体内容。
- value：一句话，说清它的核心价值，也就是看完能得到什么具体的东西，比如方法、数据、观点或案例。没有实质内容时直说。
- verdict：四选一，原样输出其中一个
  - 「值得看完整视频」：概览只是骨架，完整视频里还有概览替代不了的东西，比如演示、推导过程、画面、大量细节或案例
  - 「看概览就够」：要点都已经在概览里，看完整视频要多花不少时间，收获却不多
  - 「可以跳过」：信息量低、内容空泛，或者大部分是铺垫、广告、闲聊
  - 「信息不足」：缺失的时间段太多，或者已有的章节和金句不足以判断值不值得看
- reason：一句话说明为什么这么判断，要具体，指出是哪部分内容让你这么判断。

要求：
- 只根据给你的章节和金句判断，不要编造视频里没有的内容
- 有缺失的时间段时，不要猜测那几段讲了什么；reason 里说明判断受到了缺失内容的影响
- 判断看的是信息量和完整视频的不可替代性，不看你是否认同其中的观点
- 所有文字用简体中文；summary 不超过 80 字，value 和 reason 各不超过 50 字

输出 JSON（不要加 markdown 代码围栏）：
{"summary": "这个视频主要讲了什么", "value": "核心价值", "verdict": "看概览就够", "reason": "判断理由"}
```

## 用户提示词

```
视频标题：{videoTitle}
UP 主：{ownerName}
时长：{durationFormatted}
概览覆盖情况：{coverageNote}

视频简介：
{videoDescription}

章节摘要：
{chaptersText}

金句：
{quotesText}
```

## 变量

- `{videoTitle}` — 视频标题
- `{ownerName}` — UP 主名称
- `{durationFormatted}` — 视频时长，`MM:SS`
- `{videoDescription}` — 视频简介
- `{chaptersText}` — 每章一行：`[时间戳] 标题：摘要`；用官方总结写结论时是官方提纲，每段一行 `[时间戳] 标题：要点；要点`
- `{quotesText}` — 每条金句一行：`[时间戳] 原话`；没有金句时为 `（无）`
- `{coverageNote}` — 概览覆盖情况：完整时说明覆盖全片；有失败块时列出缺失的时间段；用官方总结写结论时注明来源
